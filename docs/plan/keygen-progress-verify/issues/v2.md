## [V2-1] `PhaseReporter` — transient single-line renderer

**Points:** 1 · **Depends on:** V1-1 · **Discharges:** PR-1, PR-3, PR-5, PR-6, PR-7, PR-9

**Description.** Add the transient-line renderer to `bins/ethernal/src/progress.rs`, per
architecture §2.2. It owns the one bit of state (`dirty`) that makes "erase before any durable
write" correct on every exit path, including error and cancel.

**Implementation notes.**

```rust
pub(crate) enum Phase { Deriving, Checking, Encrypting, Writing, Verifying }

impl Phase {
    fn label(self) -> &'static str { /* "deriving" | "checking" | "encrypting" | "writing" | "verifying" */ }
}

pub(crate) struct PhaseReporter<'a> { out: &'a mut dyn Write, mode: Progress, dirty: bool }

impl<'a> PhaseReporter<'a> {
    pub(crate) fn new(out: &'a mut dyn Write, mode: Progress) -> Self;
    pub(crate) fn phase(&mut self, i_1based: usize, total: usize, phase: Phase);
    pub(crate) fn clear(&mut self);
    pub(crate) fn out(&mut self) -> &mut dyn Write;   // clears first
}

impl Drop for PhaseReporter<'_> {
    fn drop(&mut self) { self.clear() }   // invariant I-3 on every exit path
}
```

**The `Drop` impl is load-bearing, not tidiness.** `finish_from_mnemonic` returns via `?` from
many points *after* a phase line has been drawn — `check_cancel` (`validator_cmd.rs:314`,
`:353`), `derive_path` (`:327`), the three entropy fills (`:335`–`:339`), `encrypt` (`:341`),
`write_keystore_at` (`:359`), plus the V3/V4 checks. Each of those bypasses any explicit
`clear()` call, and the error is then printed from `main.rs` — outside this struct's scope —
appended to a live `[2/3] encrypting...` line. Without `Drop`, PR-3 fails on exactly the paths
where a readable error matters most: SIGINT and a failed self-check. This mirrors
`run_ceremony`, which does result-capture specifically so `clear_after_ceremony` fires on every
exit path (`keygen.rs:135`–`139`). `clear()` is idempotent, so the explicit call before a
durable line stays correct.

- `phase()` on `Progress::Tty`: `write!(out, "\r\x1b[K[{i}/{total}] {label}...")` + flush, set
  `dirty`. **`\x1b[K` is required** — `\r` alone leaves the tail of a longer previous label on
  screen (`\rwriting` after `\rencrypting` leaves `ing`). Same CSI family the ceremony already
  emits (`keygen.rs:86`).
- `clear()`: when `dirty`, `write!(out, "\r\x1b[K")` + flush, unset. Idempotent — safe to call
  when nothing was drawn.
- `out()`: calls `clear()` then returns `&mut *self.out`, so a caller cannot write a durable
  line over a transient one.
- `Progress::NonTty`: every method is a no-op except `out()`, which just returns the writer.
- **Every** write is `let _ = …` (PR-7) — the house discipline from `emit_progress`
  (`gen_cmd.rs:373`) and `clear_after_ceremony` (`keygen.rs:99`).
- Labels are lowercase and must never contain the token `WARNING` (PR-9 —
  `tests/validator_e2e.rs:444` counts `WARNING` lines).

**Acceptance criteria.**
- [ ] Unit test: `Progress::Tty` into a `Vec<u8>` — `phase(1, 3, Encrypting)` produces
      `\r\x1b[K[1/3] encrypting...`.
- [ ] Unit test: `Progress::NonTty` into a `Vec<u8>` — the buffer is **empty** after any
      sequence of `phase`/`clear` calls, and contains no `\r` or `\x1b`.
- [ ] Unit test: `phase(…); clear();` leaves the buffer ending in `\r\x1b[K`; a second
      `clear()` appends nothing.
- [ ] Unit test: a writer that returns `Err` on every `write` does not panic and does not
      propagate (PR-7).
- [ ] Unit test (invariant I-3): a reporter dropped with a phase line on screen — i.e. without
      an explicit `clear()`, as happens on any `?` return — leaves the buffer ending in
      `\r\x1b[K`, **not** in a phase label.
- [ ] `make lint && make test` green.

**Out of scope.** Not yet wired into any loop (V2-2). No ETA/elapsed (deferred, PR-10).

## [V2-2] Wire phase reporting into `finish_from_mnemonic`

**Points:** 1 · **Depends on:** V2-1 · **Discharges:** PR-1, PR-2, PR-4, PR-8

**Description.** Report `deriving` → `encrypting` → `writing` around the existing steps of the
per-index loop (`validator_cmd.rs:313`–`375`). `checking` and `verifying` are added by V3-2 and
V4-2 as those checks land. Because `finish_from_mnemonic` is shared, `validator recover` gets
this for free (PR-8) — assert it rather than assume it.

**Implementation notes.**

- Construct the reporter once, outside the loop, from `deps.summary_out` and `deps.progress`.
  Borrow discipline: `PhaseReporter` holds `&mut dyn Write`, so the durable-line calls
  (`emit_key_progress`, `print_key_summary`) must go through `reporter.out()` rather than
  `deps.summary_out` while it is borrowed.
- Call sites (architecture §4): `Deriving` before `hd::derive_path` (`:327`), `Encrypting`
  before `encrypt` (`:341`), `Writing` before `write_keystore_at` (`:359`), then
  `reporter.clear()` before `emit_key_progress` (`:365`).
- `print_key_summary` (`:377`) must also be preceded by a clear — use `reporter.out()`.
- **Invariant I-4, add as a comment at the call site:** progress must not start before
  `run_ceremony` returns, because `clear_after_ceremony` wipes the screen
  (`validator_cmd.rs:226` runs before `:236` today; the comment documents why that ordering is
  load-bearing).
- `emit_key_progress`'s output string is **unchanged** (PR-4).

**Acceptance criteria.**
- [ ] A run that returns `Err` mid-loop (e.g. the existing cancel-mid-run fixture) leaves the
      captured buffer ending in `\r\x1b[K`, not in a phase label — the `Drop` path, exercised
      through the real loop.
- [ ] `--count 3` with `Progress::Tty` into a buffer: the buffer contains
      `[1/3] deriving`, `[1/3] encrypting`, `[1/3] writing`, … `[3/3] writing`.
- [ ] Same run: the durable lines `keystore 1/3: …` … `keystore 3/3: …` and
      `wrote 3 keystores` are present and **byte-identical** to today's format.
- [ ] `Progress::NonTty` run: buffer contains no `\r` and no `\x1b`.
- [ ] The recover path gets the same phases (extend an existing recover test's assertions —
      *adding* assertions is allowed; modifying existing ones is not).
- [ ] `secret_hygiene_key_new_buffers` (`validator_cmd.rs:1458`) and
      `secret_hygiene_key_recover_buffers` (`:1581`) pass **unmodified**.
- [ ] `make lint && make test` green.

**Out of scope.** `checking` / `verifying` labels (V3-2, V4-2). No change to
`emit_key_progress`'s text (the `verified=` k/v is V4-3).
