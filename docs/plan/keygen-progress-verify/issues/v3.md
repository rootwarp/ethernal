# V3 — C1–C3: mandatory derivation self-checks

**Discharges:** PR-11, PR-14, PR-16, PR-19 · **Depends on:** V1 (V2 for the phase label only) · **→ M3**

> These checks are **not** behind a flag (D-7). They cost microseconds; a switch to skip them
> would be a footgun with no upside. Only C4 (V4) is optional.

---

## [V3-1] `AppError::KeyVerifyFailed` + exit-code arm

**Points:** 1 · **Depends on:** — · **Discharges:** PR-14, PR-16

**Description.** A self-check failure is a crypto failure: **exit 3** (`main.rs:8`). Neither
existing route gives that — `AppError::Keystore(_)` maps to **2** for every variant except
`WrongPassphrase`/`Encrypt` (`errors.rs:260`), and `AppError::Bls(_)` falls through to the
fallback **1** (`errors.rs:74`). Add a typed variant, modelled on
`DepositError::SelfVerifyFailed` (`errors.rs:277`), so tests can match on it rather than on a
string.

**Implementation notes.**

```rust
/// A derivation or post-write self-check failed (C1–C4). Carries no key material:
/// check tag, index, HD or file path, and a secret-free detail only. Exit code 3.
KeyVerifyFailed {
    check: &'static str,   // "C1" | "C2" | "C3" | "C4"
    index: u32,
    path: String,
    detail: String,
},
```

- `Display`/`#[error(...)]`: `keystore self-check failed for index {index} ({check}): {detail}`
  — V4-2 appends the file-retention lines for the C4 case.
- `exit_code_for`: add `AppError::KeyVerifyFailed { .. } => 3` in the exit-3 block
  (`errors.rs:271`–`279`), next to `AppError::Deposit(DepositError::SelfVerifyFailed { .. })`.
- Follow the existing doc-comment convention on `AppError` variants (each states its exit code).

**Acceptance criteria.**
- [ ] `exit_code_for(&AppError::KeyVerifyFailed{..}) == 3` (unit test).
- [ ] The `Display` output contains the check tag and index and **no** secret-shaped material;
      a unit test constructs one with a plausible detail and asserts no 64-hex-char run appears.
- [ ] `make lint && make test` green.

**Out of scope.** No call site yet (V3-2).

## [V3-2] C1–C3 as three independently testable helpers + `checking` phase

**Points:** 2 · **Depends on:** V3-1, V2-2 · **Discharges:** PR-11, PR-19

**Description.** Prove, before writing anything to disk, that the derived key is internally
consistent and can actually sign. All primitives are already public
(`ethernal-core::bls`, `::hd`) — no crate change (project-plan §5 rule 6).

| Check | Assertion | Catches |
|---|---|---|
| **C1** | `new_signer(sk_bytes)?.public_key()? == derived.public_key()` | a wrong secret encrypted under the right pubkey — the operator deposits 32 ETH against a key they do not hold |
| **C2** | `validate_pubkey_bytes(pubkey)` | off-curve / small-subgroup / identity pubkey |
| **C3** | `sign(SELFCHECK_ROOT)` then `default_verifier().verify(pubkey, SELFCHECK_ROOT, sig) == true` | a key that deserializes and yields a pubkey but cannot produce a verifying signature — the same self-verify discipline `deposit gen` already applies (`deposit.rs:164`) |

**Implementation notes.**

- **Split into three private fns** — `check_c1(sk, pubkey)`, `check_c2(pubkey)`,
  `check_c3(sk, pubkey)` — plus a `verify_derived_key` that calls them in order. This is not
  cosmetic: C3's failure path is **unreachable** through `verify_derived_key` (a mismatched
  pubkey trips C1 first), so C3 is only testable if the helper can be called directly with a
  deliberately mismatched-but-valid pair. Three fns = three negative tests with **no
  production fault-injection seam** (which would itself be a security smell in a keygen tool).
- `SELFCHECK_ROOT`: `sha256(b"ethernal/keygen-selfcheck/v1")` as a `const [u8; 32]`, written
  out as a literal with the preimage in the doc comment (D-4). The probe signature is dropped
  immediately and never persisted.
- Call `verify_derived_key` **before** `encrypt` (invariant I-1) — do not spend 310 ms
  encrypting a key that fails its own check.
- Emit `Phase::Checking` immediately before the call (V2-1's label).
- Secret handling: `sk_bytes` is the caller's `Zeroizing<[u8;32]>` borrowed as `&[u8]`;
  `new_signer` copies internally and zeroizes its copy (`bls.rs` doc). Do not clone it.
- Error construction: `AppError::KeyVerifyFailed { check: "C1", index, path: path_str, detail }`
  where `detail` names *what* differed in structural terms only — e.g.
  `"public key derived from the secret does not match the derived public key"`. **Never** an
  expected/actual dump of key bytes (PR-16).

**Acceptance criteria.**
- [ ] All three checks run for every index on both `validator new` and `validator recover`;
      there is no flag that skips them (assert `--help` for both subcommands contains no
      option that disables C1–C3).
- [ ] Negative unit test per check, calling the helper directly:
      - C1: valid `sk_a` + valid `pubkey_b` → `KeyVerifyFailed{check:"C1"}`, `exit_code_for` = 3.
      - C2: all-zero (or otherwise invalid) 48-byte pubkey → `check:"C2"`, exit 3.
      - C3: `sk_a` + `pubkey_b` (both individually valid) → `check:"C3"`, exit 3.
- [ ] Positive test: a real derived key from the `ZERO_MNEMONIC` fixture passes all three.
- [ ] End-to-end unit test: with a happy path, `[1/N] checking` appears in a `Progress::Tty`
      buffer and the keystore count is unchanged.
- [ ] Failure stops the run: no keystore file exists for the failing index (C1–C3 are
      pre-write, so this is structural — assert it anyway).
- [ ] `make lint && make test` green; **no existing assertion modified**.

**Out of scope.** C4 (V4). No `--no-verify` (V4-3) — it never gates these.
