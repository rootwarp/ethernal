## [V5-1] USER-GUIDE + CHANGELOG

**Points:** 1 · **Depends on:** V4-3 · **Discharges:** PR-12 documentation

**Description.** An operator must be able to learn, without reading the source, what is
verified, what it costs, and precisely what `--no-verify` gives up.

**Implementation notes.**

- `docs/USER-GUIDE.md` § "Create BLS validator keys (`ethernal validator`)" (line ~204):
  - Add `--no-verify` to the flags table (~line 221) for both `new` and `recover`.
  - New subsection under § "Security notes (BLS)" (~line 234) — **What is verified**:
    | Check | When | Cost | Skippable |
    |---|---|---|---|
    | secret → public-key consistency | before writing | negligible | no |
    | public-key point validity | before writing | negligible | no |
    | sign/verify round trip | before writing | ~2 ms | no |
    | decrypt the written file and compare secret **and** `pubkey` field | after writing | ~0.3 s (a second scrypt) | `--no-verify` |
  - State the wall-clock consequence in operator terms: *"verification roughly doubles the
    time per key — about 0.6 s instead of 0.3 s on a modern laptop, proportionally more on
    older or air-gapped hardware. For `--count 100` that is roughly one minute instead of
    thirty seconds."* Use the measured figure from
    [`../research/r2-scrypt-cost-and-hooks.md`](../research/r2-scrypt-cost-and-hooks.md) and
    say which hardware it was measured on.
  - State what `--no-verify` does **not** skip (C1–C3), and that skipping the round trip means
    a bad write is discovered only when the key is next loaded — possibly after the deposit is
    on-chain.
- Progress output: a short note under § "`validator new` — create a new BLS key set" that a
  live phase line appears on a terminal and structured events appear when output is piped —
  and that the transient line is erased, so scripts parsing stderr see only the existing
  `keystore i/N:` lines.
- `CHANGELOG.md`: one entry covering both halves, following the file's existing format.

**Acceptance criteria.**
- [x] `--no-verify` appears in the USER-GUIDE flags table with the C1–C3 caveat.
- [x] The verification table and the measured cost statement are present, with the hardware
      named.
- [x] `CHANGELOG.md` has one entry; format matches surrounding entries.
- [x] No stale claim survives: grep the guide for any text asserting keystores are written
      without verification.

**Out of scope.** No README rewrite. No vault-note edits (handled outside the repo).

## [V5-2] e2e assertion on the `validator recover` path

**Points:** 1 · **Depends on:** V4-3 · **Discharges:** PR-8, PR-19 (integration level)

**Description.** The unit tests drive `finish_from_mnemonic` with injected deps and
`ScryptParams::FAST`. One real-binary assertion is needed so the feature is proven through the
actual process, with production scrypt, on the non-interactive path
(`tests/validator_e2e.rs:78` already runs `validator recover` with a fixed mnemonic over stdin
and returns stderr).

**Implementation notes.**

- Extend the existing helper's caller, **adding** assertions only:
  - stderr contains the `keystore 1/1:` durable line (unchanged shape).
  - stderr from a piped (non-TTY) run contains **no** `\r` and no `\x1b[` — the strongest
    end-to-end guarantee that transient rendering is TTY-only.
  - the `verified=full` marker is present on the default path.
- Add one `--no-verify` invocation asserting `verified=derived-only` and exactly one
  `WARNING` line.
- Keep the existing symlink test's "exactly one WARNING" assertion untouched and green
  (`tests/validator_e2e.rs:444`) — it runs without `--no-verify`, so the count is unaffected.
- Note the cost: this test runs production `STANDARD` scrypt twice per key. With
  `--count 1` that is ~0.6 s on this hardware — acceptable. Do not raise `--count` here.

**Acceptance criteria.**
- [x] The recover e2e asserts no `\r`/`\x1b[` on the piped path.
- [x] Default run asserts `verified=full`; `--no-verify` run asserts `verified=derived-only`
      and one `WARNING`.
- [x] The symlink WARNING-count test passes unmodified.
- [x] `make lint && make test` green; record the suite's wall-clock delta in the PR description.

**Out of scope.** No PTY/interactive `validator new` test — that tier is deferred by the
e2e-tests plan's standing scope decision (`docs/plan/e2e-tests/issues/deferred.md` on `main`).
