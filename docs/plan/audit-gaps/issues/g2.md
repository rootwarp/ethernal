# G2 — Pin GitHub Actions to full commit SHAs (1 pt · stream B · deps: —)

**Audit row flipped:** ETHSTAKER-1 (unpinned GitHub Actions) — ❌ Gap → ✅ **Mitigated (actions SHA-pinned)**
[SM-2]. Also **satisfies the gap-5 (disposition D1) prerequisite**: the future release/signing pipeline must
start from pinned actions.
**Lineage:** ETHSTAKER-1 (ToB Mar 2026) — a mutable action tag (`@v4`/`@stable`/`@v2`) lets a compromised or
retagged upstream action execute arbitrary code in CI. Low stakes today (CI only lints + tests), but a hard
prerequisite for the release pipeline.

> **Single source of truth.** This file is self-contained; [`../architecture.md`](../architecture.md) §G2
> holds the extended rationale. CI-only — no Rust, no dependency, CI semantics unchanged.

## Scope — one file, three third-party actions

`.github/workflows/ci.yml` (the **only** workflow). Three third-party `uses:`:

| Action | Current ref | Ref type |
|---|---|---|
| `actions/checkout` | `@v4` | **lightweight** tag (ref → commit; no deref) |
| `dtolnay/rust-toolchain` | `@stable` | **branch** (not a tag) — force-moves frequently |
| `Swatinem/rust-cache` | `@v2` | **annotated** tag (must deref to the commit) |

No other `ci.yml` change: `make lint` / `make test` / `make e2e-mock` / release-build steps untouched (D-G2,
G2-3).

## Resolved pins (recorded 2026-07-18 — **re-verify before commit; do not assume they are current**)

```yaml
- name: Checkout
  uses: actions/checkout@34e114876b0b11c390a56381ad16ebd13914f8d5 # v4.3.1

- name: Set up Rust
  uses: dtolnay/rust-toolchain@4cda84d5c5c54efe2404f9d843567869ab1699d4 # stable branch @ 2026-07-16
  with:
    toolchain: stable          # NEW (G2-2) — @<sha> no longer names a toolchain; select explicitly
    components: clippy, rustfmt # unchanged

- name: Cache cargo
  uses: Swatinem/rust-cache@e18b497796c12c097a38f9edb9d0641fb99eee32 # v2 (≈ v2.9.1, 2026-03-12)
```

`checkout` and `rust-cache` take no `with:` today — unchanged. Only `toolchain: stable` is *added* to
`rust-toolchain`; its existing `components: clippy, rustfmt` stays.

### The three traps (all handled above)

- **(a) `dtolnay/rust-toolchain@stable` is a BRANCH, not a tag.** The version comment cannot be a semver — use
  `# stable branch @ <date>`, not `# v1.x.y`. The `@stable` ref is **both** the action version *and* the
  toolchain selector; once pinned to a bare `@<sha>` the ref no longer names a toolchain, which is exactly why
  **`with: toolchain: stable` (G2-2) is added** — it keeps selection deterministic. The branch is
  force-updated frequently, so **`4cda84d5…` will very likely be stale by execution time — re-resolve it fresh
  and update the date comment** (see below).
- **(b) `Swatinem/rust-cache@v2` is an ANNOTATED tag.** Pin the **dereferenced commit**
  (`v2^{}` = `e18b497796c12c097a38f9edb9d0641fb99eee32`), **NOT the tag-object SHA
  `42dc69e1aa15d09112580998cf2ef0119e2e91ae`** — pinning the tag-object SHA **fails to check out**. Note `@v2`
  resolves to a changelog commit 17 s *after* the `v2.9.1` release commit (`c193711…`), so `@v2` ≠ v2.9.1;
  D-G2 pins the literal `@v2` resolution `e18b4977…` — no version upgrade, no PRD deviation.
- **(c) `actions/checkout@v4` is a lightweight tag** (SHA == commit, no deref). Stable; spot-check only.

## Re-verification step (run BEFORE committing — G2-1 acceptance; put the output in the commit/PR body)

```sh
# Deref'd commit SHAs (what goes in ci.yml):
gh api repos/actions/checkout/commits/v4            --jq .sha   # expect 34e11487…
gh api repos/dtolnay/rust-toolchain/commits/stable  --jq .sha   # MOVES OFTEN — re-resolve, update the date comment
gh api repos/Swatinem/rust-cache/commits/v2         --jq .sha   # expect e18b4977…

# Without gh — note the ^{} deref for the annotated rust-cache tag:
git ls-remote https://github.com/actions/checkout        v4
git ls-remote https://github.com/dtolnay/rust-toolchain  stable
git ls-remote https://github.com/Swatinem/rust-cache     v2        # tag-object 42dc69e1… — DO NOT PIN
git ls-remote https://github.com/Swatinem/rust-cache     'v2^{}'   # deref'd commit e18b4977… — PIN THIS
```

`dtolnay/rust-toolchain@stable` **must** be re-resolved fresh at implementation (fast-moving branch);
`checkout` / `rust-cache` are stable but spot-check them anyway. Comment style is intentionally non-uniform
(semver for checkout, branch+date for dtolnay, tag-tip note for rust-cache) — do **not** force `# vX.Y.Z` onto
dtolnay.

## Acceptance criteria (mechanically verifiable)

- [x] Every `uses:` in `.github/workflows/ci.yml` references a full **40-char** commit SHA + trailing version
      comment (`grep -nE 'uses:.*@[0-9a-f]{40}' ci.yml` matches all three; no `@v`/`@stable` tag remains). *(G2-1)*
- [x] The three SHAs match their re-verify output; annotated `rust-cache` uses the **deref'd** `e18b4977…`,
      **not** the tag-object `42dc69e1…`. *(G2-1)*
- [x] `dtolnay/rust-toolchain` carries `with: toolchain: stable`; `components: clippy, rustfmt` preserved. *(G2-2)*
- [x] No other `ci.yml` change — diff is limited to the three `uses:` lines + the one added `toolchain:` line;
      no step added/removed/reordered, no version upgrade beyond the tag's resolution. *(G2-3)*
- [x] YAML parses (no `actionlint` in the repo). *(G2-3)*
- [x] **The pushed CI run goes GREEN under the pinned actions, and its log still shows the stable toolchain
      installed with `clippy` + `rustfmt` present.** This is G2's load-bearing evidence. *(G2-2/G2-3)*

## Commit gate

`make lint && make test` green, then **one ordinary fast-forward commit on `develop`** (subject prefix `g2:`).
Note: G2 changes no Rust, so its local `make test` is **inherited-green** from the prior tip — run it to honor
the "every commit green" rule, but the real verification is the **green CI run on push** + the SHA spot-check,
not a semantically-fresh 30-min suite. Do G2 before G3/G4 so a bad pin (esp. the rust-cache annotated-tag
deref) surfaces in isolation.

## Out of scope (prevent creep)

- **No version upgrades** — pin the SHA each tag *currently resolves to*, nothing newer (checkout stays on the
  v4 line, not v7; rust-cache stays at the `@v2` tip).
- **No new action** and no new `with:` beyond `toolchain: stable`.
- **No Dependabot / Renovate config now** — wire `package-ecosystem: github-actions` when the release pipeline
  (gap 5) lands, so pins stay fresh.
- **No release / signing / attestation pipeline** — that is gap 5 / disposition **D1**, deferred; see
  [`../overview.md`](../overview.md) (do not duplicate it here).
- **No other `ci.yml` edits** (steps, triggers, matrix, caching keys).
