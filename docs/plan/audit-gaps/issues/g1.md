## Locked design decisions (D-G1)

- **Clear-on-confirm.** Automatically scrub screen + scrollback the moment the re-entry ceremony ends — no
  prompt, no opt-out flag.
- **Raw hard-coded ANSI**, written to the **same `/dev/tty` handle used for display** (never stdout/stderr/
  logger — S-1). No terminfo, no `crossterm`, **no new dependency** (D-1).
- **Whole `ESC[2J ESC[3J ESC[H` group emitted TWICE**, then flushed. The "twice" is load-bearing: iTerm2 does
  not fully clear on a single pass (upstream ethstaker PR #242). Order is load-bearing: erase-screen (`2J`) →
  erase-scrollback (`3J`) → home (`H`); do **not** move `H` first.
- **Fail-open.** A failed clear-write never turns a completed ceremony into an error; it prints an actionable
  manual-clear warning and continues, exit code unchanged.
- **Result-capture body** so the clear fires on **every** post-display exit path (not the stash's implicit
  returns, if that is what the pop reveals).
- **Multiplexer caveat documented**, not solved — `3J` cannot reach tmux/screen history from the child.

## New items + signatures (in `key_cmd.rs`, next to `run_ceremony`)

```rust
/// ESC[2J (erase screen) · ESC[3J (erase scrollback) · ESC[H (home), the whole
/// group TWICE — iTerm2 needs a second pass (upstream ethstaker PR #242). Order
/// is load-bearing: erase-screen → erase-scrollback → home.
const CLEAR_SCROLLBACK_TWICE: &[u8] = b"\x1b[2J\x1b[3J\x1b[H\x1b[2J\x1b[3J\x1b[H";

/// Post-ceremony scrub on the SAME display TTY (S-1: never stdout/stderr/logger).
/// Infallible & fail-open (G1-2): on a clear-write error, print manual-clear
/// instructions to `tty`, falling back to `warn_out` (stderr in prod); never
/// changes the ceremony's exit status. On success, print the notice + tmux/screen
/// caveat to the now-blank `tty` (G1-3).
fn clear_after_ceremony(tty: &mut dyn Write, warn_out: &mut dyn Write) {
    let cleared = tty.write_all(CLEAR_SCROLLBACK_TWICE).and_then(|_| tty.flush()).is_ok();
    if cleared {
        let _ = writeln!(tty, "The terminal was cleared to remove the displayed mnemonic.");
        let _ = writeln!(tty, "  Note: a terminal multiplexer keeps its own scrollback — \
                               tmux: `tmux clear-history`; screen: C-a : then `scrollback 0`.");
        let _ = tty.flush();
    } else {
        // Fail-open. macOS Terminal.app makes this the PRIMARY scrub path (ESC[3J
        // unreliable there), so the instructions must be genuinely actionable.
        let msg = "WARNING: could not clear the terminal automatically; the mnemonic may \
                   remain in scrollback.\n  Clear it manually: `clear && printf '\\x1b[3J'`  \
                   (macOS Terminal.app: press Cmd+K).\n";
        if tty.write_all(msg.as_bytes()).and_then(|_| tty.flush()).is_err() {
            let _ = warn_out.write_all(msg.as_bytes());
            let _ = warn_out.flush();
        }
    }
}
```

`run_ceremony` gains one parameter and a result-capture body (its current body becomes a private

```rust
pub(crate) fn run_ceremony(
    mnemonic: &str,
    tty: &mut dyn Write,
    warn_out: &mut dyn Write,          // NEW — stderr fallback for the fail-open clear (G1-2)
    src: &dyn MnemonicSource,

    clear_after_ceremony(tty, warn_out);                     // EVERY post-display path (G1-1)

```

`deps.tty_writer` and `deps.summary_out` are **disjoint `&mut dyn Write` fields** → the two reborrows compile
with no aliasing error. `summary_out` is already the injection struct's stderr fallback, so it is the correct
dependency-free fallback for the fail-open clear.

**Why result-capture (not per-branch scrubs):** clearing after the *whole* `ceremony_body` covers all five
post-display paths with one structure. It is deliberate that the scrub runs after the full body, not just
after the display `writeln!`: the re-entry reads via `src.read_line` with **echo ON** (`key_cmd.rs:456`), so
the operator re-typing all 24 words also lands in scrollback — scrubbing after the whole body removes both.

### The five post-display paths the clear MUST cover (D-G1 acceptance property)

1. Successful confirm (`Ok`).
2. Mismatch-abort → `Err(Aborted)` (exit 4).
3. Read error.
4. SIGINT / cancel.
5. **Partial display write** (the display `writeln!…map_err(exit2)` failing mid-mnemonic).

Drive `run_ceremony` directly (now `pub(crate)`) with a scripted re-entry source and two `Vec<u8>` writers.
The four tests map 1:1 to the acceptance criteria:

1. **`clear_sequence_bytes_and_order`** — correct re-entry → `Ok`; assert the tty buffer **contains
   `CLEAR_SCROLLBACK_TWICE`** (doubled group) **and** the clear's byte offset > the mnemonic's offset
   (clear-after-display ordering); assert the G1-3 notice + `tmux`/`screen` text present.
2. **`abort_path_still_clears`** — mismatch re-entry → `Err(Aborted)` (exit 4) **and** the tty buffer contains
   `CLEAR_SCROLLBACK_TWICE` (the scrub fired despite the abort).
3. **`clear_failure_warns_on_fallback`** *(security-relevant)* — display succeeds, the clear write fails;
   assert `run_ceremony` still returns `Ok`, the tty received no clear bytes past the display, and **`warn_out`
   (the stderr `Vec`) contains the manual-clear instructions** (`Cmd+K` / `clear &&`).
4. **`success_prints_notice`** — clean clear → the notice + multiplexer caveat land on the tty. (May be folded
   into test 1.)

### ⚠ Writer-trap fix (must-do) — do NOT use an ESC-sniffing writer

A writer that "fails on any write containing `0x1b`" is **wrong**: the manual-clear string holds the *literal
text* `printf '\x1b[3J'`, i.e. the bytes `\`,`x`,`1`,`b` — **no real ESC** — so an ESC-sniffing writer would
let the warning-to-tty *succeed* and the stderr fallback would never be exercised (the assertion passes
vacuously). Use a writer that **fails all writes/flushes after the display's first `flush()`**:

```rust
struct FailAfterDisplay { display_flushed: bool }
impl Write for FailAfterDisplay {
    fn write(&mut self, b: &[u8]) -> io::Result<usize> {
        if self.display_flushed { Err(io::Error::new(io::ErrorKind::BrokenPipe, "tty gone")) }
        else { Ok(b.len()) }
    }
    fn flush(&mut self) -> io::Result<()> {
        if self.display_flushed { return Err(io::Error::new(io::ErrorKind::BrokenPipe, "tty gone")); }
        self.display_flushed = true;   // the display's terminal flush; everything after fails
        Ok(())
    }
}
```

The display body ends with `.and_then(|_| tty.flush())` and there are no tty writes between it and the clear,
so that flush is a clean seam: both the clear *and* the warning-to-tty fail, and `warn_out` genuinely receives
the message. **No pty harness** (locked non-goal): the pipe-driven E2E suites exercise `recover`, which has no
ceremony. Account coverage is by construction (same `run_ceremony`); an optional `account_cmd.rs` smoke test
asserting `run_account_new_with_deps` routes the clear to its `tty_writer` is nice-to-have, not required.

**Existing tests stay green unmodified:** every `key new` tty assertion is `contains`/`!contains`-based
(`:1040`, `:1100`, `:1777`, secret-hygiene `:1845-1849`), so append-only clear bytes + notice cannot falsify
them and the notice carries no seed/SK/passphrase/`TREZOR` bytes. Recover tty assertions (`:1524` `!contains`,
`:1657`/`:1896` `is_empty`) are untouched (recover never calls `run_ceremony`).
`ceremony_tty_write_failure_exit2_no_files` (`:1145`) stays green (the clear runs fail-open into the summary

## Out of scope (prevent creep)

- **No prompt-to-clear, no opt-in/opt-out flag** — the locked decision is automatic clear-on-confirm.
- **No terminfo / ncurses / `crossterm` / subprocess** (`clear`/`tput`/`reset`) — raw hard-coded ANSI only,
  no new dependency. Do **not** copy upstream's subprocess approach.
- **No pty test harness.**
- **No drop guard / panic-window fix** — the repo has none; a panic between display and clear skipping the
  scrub is the stated, accepted residual (below), same posture as the rest of the binary.
- **No change to recover flows**, entropy sourcing, TTY-only fail-closed display, or exit codes.
- **No attempt to clear multiplexer history from the child** — documented caveat only.

## Residual risk (accepted, stated so SM-1 is auditable)

On the fail-open path, and in a panic between display and clear (no drop guard), the mnemonic remains in
scrollback — the operator is warned in the former; the latter is a stated residual. `3J` clears the emulator's
scrollback but cannot reach a terminal multiplexer's own history — documented, not fixable from the child.
This is why SM-1 reads "Mitigated (success path)," not an unconditional scrub.
