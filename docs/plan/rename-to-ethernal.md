# Plan — Rename `eth-deposit` → `ethernal`

**Status:** approved (ready to implement)  
**Date:** 2026-07-18  
**Goal:** Rebrand the CLI, workspace crates, crate directories, env contract, and GitHub repository from the transitional `eth-deposit` / `eth-utils` names to **`ethernal`**, without changing deposit-pipeline behavior.

---

## Locked decisions (2026-07-18)

| # | Question | Decision |
|---|---|---|
| 1 | Env middle segment `_TX_` | **Keep** — `ETH_DEPOSIT_TX_*` → **`ETHERNAL_TX_*`** (incl. `ETHERNAL_TX_PRIVATE_KEY`) for continuity with the current contract. |
| 2 | Crate directory paths | **Rename** — `crates/core` → **`crates/ethernal-core`**, etc. (package name and path match). |
| 3 | GitHub repo | **Rename** — `rootwarp/eth-utils` → **`rootwarp/ethernal`** (final issue **R6**, after code lands). |
| — | Dual-accept old env names | **No** (tool still unreleased). |
| — | Protocol words (`deposit`, deposit_data JSON, SSZ) | **Keep** (not product branding). |

---

## Why now

- Product name is **`ethernal`**; `eth-deposit` is the port-era / merge-era technical name (`eth-deposit-gen` + `eth-deposit-tx` → single binary).
- Version is still **`0.1.0` unreleased** — no tagged `eth-deposit` binary under the merged name, so a hard rename is cheap (no dual-ship period required).
- String surface is large but mechanical: ~60 files with `eth-deposit`, ~32 Rust files with `eth_deposit_*` imports, ~19 files with `ETH_DEPOSIT*`.

## R1 — Library crates: dirs + names + imports

**Goal:** Package names, lib names, directory paths, and `use` paths are all `ethernal_*` / `crates/ethernal-*`.

**Steps**
1. `git mv crates/core crates/ethernal-core`  
   `git mv crates/keystore crates/ethernal-keystore`  
   `git mv crates/signer crates/ethernal-signer`  
   `git mv crates/tx crates/ethernal-tx`
2. Root `Cargo.toml`: workspace deps  
   `ethernal-core = { path = "crates/ethernal-core" }` (and siblings).
3. Each crate `Cargo.toml`: `[package] name = "ethernal-…"`, `[lib] name = "ethernal_…"` if present; fix internal path deps between crates.
4. All dependents: `use ethernal_*`; workspace dependency keys.
5. `cargo build --workspace` → refresh `Cargo.lock`.

**Acceptance**
- [ ] Dirs are `crates/ethernal-{core,keystore,signer,tx}` only (no `crates/core` etc.)
- [ ] `cargo test --workspace` green
- [ ] No `eth-deposit-*` package names; no `eth_deposit_` Rust paths in live source

## R6 — GitHub repository rename

**Goal:** Canonical remote is `github.com/rootwarp/ethernal`.

**Prerequisites**
- R1–R5 merged to `develop` (or this work already is the tip of `develop`).
- Actor has permission to rename the repo (org owner / admin).
- No open external clones that will break without notice (optional: announce first).

**Steps**
1. Rename on GitHub:

```bash
gh repo rename ethernal --repo rootwarp/eth-utils
# or: GitHub UI → Settings → General → Repository name
```

   GitHub leaves redirects from the old name for git clone/push for a time; do not rely on that forever.

2. Local remotes (every clone):

```bash
git remote set-url origin git@github.com:rootwarp/ethernal.git
# verify
git remote -v
git fetch origin
```

3. Update any remaining clone/badge URLs in README or docs that still say `eth-utils` (if not already fixed in R4).
4. Check GitHub Actions, branch protection, and secrets still attached to the renamed repo (usually automatic).
5. Optional: update local directory name `~/git/rootwarp/eth-utils` → `ethernal` (filesystem only; not git history).

**Acceptance**
- [ ] `gh repo view rootwarp/ethernal` succeeds
- [ ] `git push` / CI on `develop` work against the new remote
- [ ] README clone instructions (if any) use `ethernal`
- [ ] Progress log records R6 done with new URL

**Risks**
- External bookmarks, local clone paths, and CI on forks need a one-time update.
- Graphite / other tooling may cache the old repo name — re-auth or re-point if needed.
