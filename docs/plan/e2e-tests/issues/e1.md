## [E1-1] Scrypt debug-profile override (workspace `Cargo.toml`)

**Points:** 1 · **Depends on:** — · **Discharges:** build-config prerequisite for the recover-path scrypt
(T-3 and the existing suite), the hoodi-decrypt goldens (T-7/T-19), and the live gen (T-6) ·
**Production-tree touch** (build config only)

**Description.** Add the targeted scrypt optimization to the workspace root `Cargo.toml` so the debug binary
`cargo test` drives never runs production-cost scrypt (`n=262144`) unoptimized. **Justified by the recover
path** (the PTY ceremony tests that originally motivated it are deferred): `key recover` / `account recover`
encrypt each keystore at `ScryptParams::STANDARD`, with **no cheap-param hook** (S-4 forbids injection;
`account_recover_help_has_no_entropy_or_time_flag` asserts its absence). **Measured on develop @ `584c404`**
(`account_e2e::account_recover_keystores_match_fixture`, COUNT=2 keystores):

| Profile | Test wall-time | Per keystore |
|---|---|---|
| debug default (no override) | ~39 s | ~19–20 s |
| `[profile.dev.package.scrypt] opt-level = 3` | ~1.2 s | ~0.6 s |

~19 s/keystore unoptimized is far above the 5 s threshold, and the existing suite already pays it. Land it
first, ahead of anything scrypt-touching.

**Implementation notes.** Workspace root `Cargo.toml` currently has `resolver = "2"` (`Cargo.toml:2`) and
**no `[profile.*]` sections**. Add:
```toml
[profile.dev.package.scrypt]
opt-level = 3
```
Blast radius: only the `scrypt` crate is optimized under the dev-derived profile `cargo test` uses; every
workspace crate and every other dependency stays `opt-level = 0`, so incremental workspace builds are
unaffected (architecture §"Scrypt debug-speed override"). Robust fallback if a future scrypt moves its hot
loop into its `salsa20` dep: `[profile.dev.package."*"] opt-level = 2`. No runtime or release-artifact
behavior changes.

**Acceptance criteria.**
- [x] `grep -A1 'profile.dev.package.scrypt' Cargo.toml` shows `opt-level = 3`; no other `[profile.*]` added.
- [x] `cargo build --tests` green; diff is limited to the two-line profile section.
- [x] `make lint && make test` green — and the recover-path e2e tests are materially faster (spot-check
      `account_e2e::account_recover_keystores_match_fixture` drops from ~39 s to ~1–2 s).

**Out of scope.** No whole-profile opt bump; no other `Cargo.toml` change; no `src/` change.
