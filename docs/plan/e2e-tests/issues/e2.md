## [E2-1] `decrypt_v3` behind an `ethernal-keystore` `test-support` feature

**Points:** 3 · **Stream:** B · **Depends on:** — · **Discharges:** enables T-3 (consumed by E3-1)
· **Production-tree touch** (feature-gated, compiled out of release)

**Description.** Add a test-only v3 (Web3 Secret Storage) decrypt behind a crate feature, reusing
`ethernal-keystore`'s in-crate crypto so it cannot drift from the `encrypt_v3` writer. This restores the
encrypt↔decrypt symmetry the v4 `Loader` round-trip already gives BLS, and lets T-3 prove the v3 **encrypt**
path (the top-level `address` is written independent of the ciphertext, `encrypt_v3.rs:183`, so
address-match alone leaves it unverified — D-4/R4).

**Implementation notes.**
- `crates/ethernal-keystore/Cargo.toml`: `[features]` → `test-support = []` (no section today).
- `crates/ethernal-keystore/src/decrypt_v3.rs` (new, ~35 lines, `#[cfg(feature = "test-support")]`): parse
  v3 JSON → `derive_scrypt(RAW password, salt, n, r, p, dklen)` → verify `v3_mac` (**MAC-before-decrypt**,
  constant-time compare) → `Aes128Ctr` → `Zeroizing<[u8;32]>`. **Reuse `crypto::{derive_scrypt, Aes128Ctr,
  v3_mac}` verbatim** (crate-internal at `crypto.rs:13,69,135`). Use **RAW passphrase bytes** (v3 does not
  apply the EIP-2335 NFKD normalization).
- `crates/ethernal-keystore/src/lib.rs`: `#[cfg(feature = "test-support")] mod decrypt_v3; #[cfg(feature =
  "test-support")] pub use decrypt_v3::decrypt_v3;`.
- `bins/ethernal/Cargo.toml`: one `[dev-dependencies]` line — `ethernal-keystore = { workspace = true,
  features = ["test-support"] }` — **test-only**, solely to flip the feature on for test builds (the bin
  already depends on the crate in `[dependencies]`).
- A crate unit test asserting `decrypt_v3` round-trips an `encrypt_v3` output.
- **Stays-out-of-release invariant (binding seq. #8), stated in the `decrypt_v3.rs` module header:** under
  `resolver = "2"` (`Cargo.toml:2`), dev-dependency features are unified **only** for test/bench/example
  builds, so `cargo build --release --bin ethernal` does not enable `test-support` and `decrypt_v3` is
  `#[cfg]`-compiled out. The `cargo tree -e normal` inspection is a best-effort backstop that *documents*
  (does not guarantee) the property; the guarantee is the cfg gate + resolver 2.

**Precise production-tree scope.** The genuine production-tree change is `crates/ethernal-keystore/src/decrypt_v3.rs`
+ the `lib.rs` re-export + the `[features]` line. The `bins/ethernal/Cargo.toml` `[dev-dependencies]` line
is test-only build config.

**Acceptance criteria.**
- [x] `cargo test -p ethernal-keystore --features test-support` green (encrypt↔decrypt round-trip).
- [x] `decrypt_v3.rs` module header states the resolver-2 + `#[cfg]` stays-out-of-release invariant.
- [x] Backstop: `cargo build --release --bin ethernal` then `cargo tree -e normal -p ethernal` shows no
      `test-support` feature enabled on `ethernal-keystore`.
- [x] `make lint && make test` green.

**Out of scope.** No **in-binary** v3 reader (Q3 veto — never ship one); no product code path consumes
`decrypt_v3`; no new third-party dependency or lockfile entry.
