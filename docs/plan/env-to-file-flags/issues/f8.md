## [F8-1] `USER-GUIDE.md` + `README.md` — sweep and the three new pieces of prose

**Points:** 1 · **Depends on:** F4-2, F5-1, F6-1 · **Discharges:** FR-11, FR-20, FR-36, FR-38

**Description.** **This is not only a rename sweep.** Three pieces of genuinely new prose ride
with the 55 mechanical replacements.

**Implementation notes.**

1. **FR-11 — the byte rule, in bytes.** `printf '%s' pw > f` vs `echo pw > f`, an explicit note
   that a trailing **space** is significant, and the one-sentence form:
   > *"The secret is the whole file minus at most one trailing newline; a carriage return anywhere
   > is an error."*
2. **The "deliberately unlike prior art" list gains two rows:**
   - **multi-line** — a *deliberate divergence, not parity*: geth accepts multi-line files
     because `--password` is a password **list** indexed per unlocked account, a feature ethernal
     does not have.
   - **non-UTF-8**, beside the CRLF row — geth's Go strings are byte strings and would accept
     those bytes; D-3 refuses them, and the guide must say **why** (architecture §3, §11
     divergence 6): no capability is lost, because `std::env::var` already errored on non-UTF-8,
     and refusing stays the reversible direction.
3. **FR-20 — the mirror-image footgun**, in the same register as the existing
   raw-`--mnemonic-passphrase` warning (`USER-GUIDE.md:237`): a *passphrase* typed where a *path*
   is expected lands in argv, `ps`, shell history, **and the not-found error message**. There is
   no shape to key on, so documentation is the mitigation.
4. **FR-38:** `USER-GUIDE.md:197-200`'s "two passphrases are never interchangeable" section is
   rewritten for files and carries the FR-8 byte rule.
5. **FR-36:** every `export VAR=secret` example becomes a file example that does **not** create a
   world-readable file — `umask 077`, `chmod 600`, or process substitution. Where the guide
   recommends the no-disk-file pattern it names `<(...)`, and mentions `/dev/fd/N` only as the
   general escape hatch — **not `/dev/stdin` alone** (FR-6's collision).
6. Mention the FR-24 regression where the guide shows `tx sign --signer local`:
   `--private-key-file` is now **required**.

**Acceptance criteria.**
- [ ] `rg -c -- '--(passphrase|private-key|mnemonic-passphrase)-env' docs/USER-GUIDE.md README.md`
      returns **zero** for both files (baseline 53 and 2).
- [ ] The FR-11 byte rule appears with **both** `printf '%s'` and `echo` shown, the
      trailing-space note, and the one-sentence form verbatim.
- [ ] The "deliberately unlike prior art" list contains a **multi-line** row and a **non-UTF-8**
      row, each stating the reason, beside the existing CRLF row.
- [ ] The FR-20 warning names argv, `ps`, shell history **and the not-found error message**.
- [ ] `rg -n 'export [A-Z_]+=' docs/USER-GUIDE.md README.md` shows no example that creates a
      world-readable secret file — every remaining one is `umask 077`, `chmod 600`, or `<(...)`.
- [ ] **Every new command block is copy-pasteable, and was actually pasted once** — record which
      ones in the completion note.
- [ ] No stale claim survives: `rg -n 'environment variable' docs/USER-GUIDE.md README.md` shows
      no line presenting env as the secret source for a passphrase or key.

**Out of scope.** `CHANGELOG.md` and the acceptance sweep (F8-2). The `verify` skill (landed in
F5-1).

## [F8-2] `CHANGELOG.md` + the acceptance `rg` sweep

**Points:** 1 · **Depends on:** F8-1 (and, by the phase rule, F4, F5 and F6 merged) ·
**Discharges:** FR-37, PRD §8 acceptance

**Description.** Record the break, then run the PRD's mechanical acceptance check and paste its
output. **Run before F4/F5/F6 merge it passes vacuously** (R-6, plan §5 rule 7).

**Implementation notes.**

1. `CHANGELOG.md` gains a `### Removed` heading naming **all three** flags with a **migration
   line each**, and states the **FR-24 zero-flag regression explicitly**: `ethernal tx sign
   --signer local` no longer works with no key flag, because `--private-key-env` had
   `default_value(DEFAULT_PRIV_KEY_ENV)` and there is no defensible default *path*.
2. Record it as a **breaking change** (A-3): no deprecation window, and no `#[deprecated]`
   anywhere (D-10). Note that the **library** items `EnvSource` and `new_local_signer_from_env`
   are **retained** (A-2, M-5) — only the flags are removed.

   ```
   rg -- '--(passphrase|private-key|mnemonic-passphrase)-env' bins/ crates/ docs/ README.md .claude/skills/
   ```
