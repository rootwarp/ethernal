## [F3-1] `common::secret_file` fixture helper

**Points:** 1 · **Depends on:** — · **Discharges:** R-7 mitigation; **blocks every
test-migration issue** (plan §5 rule 2)

**Description.** The 63 real `-env` call sites across the integration suite are **not** a string
swap: each `.env(KEY_ENV, VALUE)` + `--private-key-env KEY_ENV` pair becomes tempdir + write +
`chmod 600` + path. One helper turns all of them into one-line calls.

**Implementation notes.**

1. In `bins/ethernal/tests/common/mod.rs`, beside `ethernal()`:
   ```rust
   /// Writes `bytes` to `dir/name` at mode 0600 and returns the path. Every test
   /// secret file must go through this: a 0644 file emits the FR-17 WARNING and
   /// breaks the caller's own WARNING count.
   pub fn secret_file(dir: &TempDir, name: &str, bytes: &[u8]) -> PathBuf;
   ```
2. **Writes with no trailing newline**, so fixtures do not silently exercise FR-8 where a test
   meant to exercise something else. A test that *wants* a trailing `\n` passes it in `bytes`.
3. `common/mod.rs` already carries `#![allow(dead_code)]` (`:14`), so the helper lands green
   ahead of its first caller.
4. Create at mode 0600 via `OpenOptionsExt::mode(0o600)` (`fs_util.rs:87` /
   `open_0600` shape), then `set_permissions(0o600)` **before** writing payload
   (`write_atomic` umask hardening). Never write-then-chmod. No new dependency.

**Acceptance criteria.**
- [x] One test proving the helper: a file written through it reports mode `0600` and its bytes
      end **without** `\n`.
- [x] A second assertion that the returned path is inside the passed `TempDir`.
- [x] `git diff --name-only` touches only `bins/ethernal/tests/common/mod.rs`.
- [x] `make lint && make test` green — the helper is dead code at this point and must not warn
      under `clippy --workspace --all-targets -- -D warnings`.

**Out of scope.** No call site uses it yet. No allowlist change (that is F6-3's FR-35 work in the
same file — line-disjoint).

## [F3-2] Make the six WARNING counters warning-kind-specific

**Points:** 1 · **Depends on:** — · **Discharges:** FR-21, R-3

**Description.** Six assertions count `WARNING` lines and require **exactly one** — architecture
§9 corrects the PRD's inventory of three. Four are at risk once a test passes a secret-file flag;
two are structurally immune. Each at-risk one becomes specific to its warning **kind**, on a
discriminating token. **None is loosened to "at least one"** (plan §5 rule 6).

**Implementation notes.**

1. The four at-risk counters, from architecture §9:

   | Site | Counts | Discriminating token |
   |---|---|---|
   | `bins/ethernal/tests/validator_e2e.rs:495-499` | `--no-verify` | the `--no-verify` notice's own text |
   | `bins/ethernal/tests/validator_e2e.rs:526-530` | symlinked output dir | the symlink warning's own text |
   | `bins/ethernal/src/validator_cli.rs:543-548` | banner | that banner's own text |
   | `bins/ethernal/src/account_cli.rs:496-500` | banner | that banner's own text |

   R3's token for FR-17's kind is **`file permissions`** — it appears in no other message, is not
   a flag name (so it survives F4/F5/F6's rename) and is not a path (so it is host-independent).
2. The two structurally-immune counters — `bins/ethernal/src/fs_util.rs:269-273` (unit,
   `Vec<u8>` sink) and `bins/ethernal/src/validator_cmd.rs:2527-2535` (unit, `FixedPassphrase`)
   — gain a **one-line comment recording why they are immune** (no file flag is in play), so a
   later reader does not "fix" them.
3. **Scope note for the reviewer:** project-plan §2 F3's diff-scope sentence names
   `validator_cli.rs` and `account_cli.rs` only, while the same paragraph requires the comments
   in `fs_util.rs` and `validator_cmd.rs`. All four source files are touched, **all four inside
   `#[cfg(test)]` modules only**. This is not scope creep; it is the paragraph's own body.

**Acceptance criteria.**
- [x] Each of the four at-risk counters asserts `== 1` on a token that is **neither a flag name**
      (so it survives the rename) **nor a path** (so it is host-independent).
- [x] No counter is weakened to `>= 1`; `git diff` shows no `assert!(… >= 1)` or
      `assert!(!… .is_empty())` replacing an equality.
- [x] The two immune counters carry a one-line "why immune" comment and are otherwise unchanged.
- [x] `git diff --name-only` touches only `bins/ethernal/tests/validator_e2e.rs`,
      `bins/ethernal/src/validator_cli.rs`, `bins/ethernal/src/account_cli.rs`,
      `bins/ethernal/src/validator_cmd.rs` and `bins/ethernal/src/fs_util.rs`; every hunk in the
      four `src/` files is inside a `#[cfg(test)]` module. **Zero production behavior changed.**
- [x] `make lint && make test` green **against today's code** — the hardening is behavior-neutral,
      and that is the whole point of doing it before the flags move.

**Out of scope.** No new warning. No flag rename. No new test case.
