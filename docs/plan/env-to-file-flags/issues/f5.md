## [F5-1] Flip `deposit gen` and hoist the read above the worker pool

**Points:** 2 · **Depends on:** F2-1, F3-1 · **Discharges:** FR-2, FR-4, FR-5, FR-6, FR-22 (gen
site), D-5

**Description.** The atomic flip for stream B, plus the D-5 restructure that makes a file usable
at all with `--parallel > 1`.

**Implementation notes.**

1. **`bins/ethernal/src/gen_cli.rs`** — `:122` defines its own passphrase flag (it does **not**
   use `shared_args()`, which is why this stream is independent of F4). Remove `--passphrase-env`,
   add `--passphrase-file` with `value_name("PATH")`; `GenConfig.passphrase_env: String`
   (`gen_cli.rs:33`) → `passphrase_file: Option<PathBuf>` (FR-4); update the `override_usage`
   string at `:71` (FR-2); route the argument through `fs_util::secret_file_arg` (FR-6).
2. **`bins/ethernal/src/gen_cmd.rs:143`** — read **once, before the pool**, into the established
   in-process source (architecture §6.2):
   ```rust
   let file_pw; let tty_source;
   let pw_src: &(dyn PassphraseSource + Sync) = if let Some(p) = &cfg.passphrase_file {
       // The single read (FR-22). InMemoryPassphrase is the established in-process
       // source (keystore_cli.rs:170, C4's D-6) and is Sync.
       let src = FileSource::new(p.clone(), std::io::stderr());
       file_pw = InMemoryPassphrase::new(src.read().map_err(AppError::Keystore)?);
       &file_pw
   } else {
       tty_source = TermPromptSource::new(std::io::stderr());
       &tty_source
   };
   ```
3. **The `TermPromptSource` branch is unchanged** — one prompt per pubkey, today's behavior.
   That is a pre-existing UX wart and hoisting it would change interactive behavior beyond this
   change's scope (architecture §6.2, recorded as a non-change so a reviewer does not read it as
   an oversight).
4. **`.claude/skills/verify/SKILL.md`** — all 3 occurrences are `deposit gen`, and the skill is
   **executable, not prose**, so it cannot wait for F8. `KEYSTORE_PASSPHRASE=$(cat
   testdata/hoodi/passphrase.txt)` becomes
   `--passphrase-file testdata/hoodi/passphrase.txt` passed directly. The skill records that the
   tracked fixture is `100644` (git cannot store 0600), so **an FR-17 `file permissions` WARNING
   is expected and correct** on that run.
5. **Test migration:** `gen.rs` (17 remaining occurrences) and `e2e_live.rs:97`, all through
   `common::secret_file`.
6. **`--parallel` is untouched**; so are keystore bytes, filenames and output mode (plan §5
   rule 8).

## [F5-2] Read-once evidence: FIFO, fail-fast, and the S-B regression row

**Points:** 1 · **Depends on:** F5-1 · **Discharges:** FR-22 (evidence), FR-12 (S-B row)

**Description.** F5-1's hoist is only load-bearing if a test fails when it is reverted. Three
assertions make that true, plus the S-B row that guards the normalizer.

**Implementation notes.**

1. **FIFO under a wall-clock timeout.** A named `mkfifo` FIFO as `--passphrase-file` with
   `--parallel 4` must **complete**. The measured failure is an **indefinite block, not an
   error** (R4 M-d), so the test must impose its own timeout and fail rather than hang CI —
   spawn the child, wait with a deadline, kill and fail on expiry. Create the FIFO by shelling
   out to `mkfifo` (no new dependency, M-4) and start the writer **before** the read.
2. **Fail-fast.** A short or otherwise invalid passphrase file fails **before any worker starts**
   — asserted by **exit 2 and zero output files**, not by the pre-change mid-pool exit 3 on an
   arbitrary pubkey. This is D-5's deliberate side effect and an improvement.
3. **S-B regression row (FR-12):** `pw` vs `pw\n` produce an identical `deposit_data*.json`.
   **The test comment must state that this row passes with or without FR-8** —
   `normalize_passphrase` strips both `\n` and `\r` at `u <= 0x1f` (`crypto.rs:52`) — so it is a
   **normalizer guard, not byte-rule evidence**. The evidence rows are F4-3's S-C and S-D.
4. Keep the pubkey count at the minimum that exercises `--parallel 4`; these are production-scrypt
   runs.

**Acceptance criteria.**
- [ ] `--parallel 4` with a named FIFO completes under an explicit wall-clock deadline; the test
      fails (does not hang) if the read-once fix is reverted.
- [ ] A 7-character passphrase file: exit 2, **and the output directory contains zero files** —
      asserted, not inferred from the exit code.
- [ ] S-B row: `pw` vs `pw\n` → byte-identical `deposit_data*.json`, with the "passes with or
      without FR-8" comment present.
- [ ] No assertion in this issue is the *only* evidence for FR-9 — a comment points at F4-3.
- [ ] `make lint && make test`, `make e2e-mock` green, **and `make e2e-live` re-run locally**
      (R-8).

**Out of scope.** S-C / S-D and the CR rows (F4-3). The `tx run` FIFO test (F6-2 — a different
code path with a different gate).
