## [F1-1] New crate, file policy, and the fixed-buffer read loop

**Points:** 2 · **Depends on:** — · **Discharges:** FR-13, FR-14, FR-15, FR-16, FR-17, FR-23

**Description.** Create `crates/ethernal-secretfile` and the private `read_capped` body
(architecture §2.3) that every entry point shares: open (following symlinks), `fstat` the open
descriptor, reject directories, warn on loose permissions, and fill one fixed buffer that is
never grown. No byte rule and no UTF-8 handling yet — that is F1-2.

**Implementation notes.**

1. `crates/ethernal-secretfile/Cargo.toml` — dependencies **exactly** `zeroize` and `thiserror`,
   both already in `[workspace.dependencies]`. Workspace members are globbed and every
   make/CI target is `--workspace`, so no other file needs editing to pick the crate up.
2. Public items from architecture §2.2: `MAX_SECRET_FILE_BYTES = 4096`, `Residual`,
   `SecretFileError` (all seven variants). `read_capped` stays **private** — no consumer may
   bypass a byte rule.
3. The loop is architecture §2.3 verbatim in shape:
   - `File::open` → `classify_open` into `NotFound` / `PermissionDenied` / `Io`.
   - `f.metadata()` — `fstat` on the **open descriptor**, following OpenSSH `authfile.c:82-87`,
     so the mode checked, the type checked and the bytes read are the same inode (FR-15,
     TOCTOU-free).
   - `md.is_dir()` → `IsDirectory`. Measured: `File::open("/tmp")` **succeeds** (R4 M-b).
   - `ft.is_file() && md.len() > MAX` → `TooLarge`. **Regular files only, and never the
     enforcement**: `/dev/zero` reports `len() == 0` (R4 M-a) and a pipe reports an arbitrary
     snapshot of buffered bytes — 0 on Linux, measured 9 for a 9-byte payload on macOS (R4 §3).
   - `#[cfg(unix)]` FR-17 warning on `ft.is_file() && mode & 0o077 != 0`, wording from FR-17.
   - One `Zeroizing::new(vec![0u8; MAX + 1])`, `read` in a loop, `continue` on `Interrupted`,
     `break` on `Ok(0)`, `n > MAX` → `TooLarge`, `truncate(n)`.
   - `read_exact` is wrong (a FIFO delivers short reads) and `take(..).read_to_end(..)` relies on
     an unspecified reserve strategy.
4. **FIFO and `/dev/zero` tests need no new dependency and must not block.** `mkfifo` is not in
   `std`: create the FIFO by shelling out with `std::process::Command::new("mkfifo")`, and start
   the writer (a spawned `sh -c 'printf … > fifo'` or a thread) **before** the read, or the test
   hangs. Gate FIFO and `/dev/zero` cases `#[cfg(unix)]`.
5. The mode-`0000` → `PermissionDenied` case does not hold when the suite runs as **root**; note
   that in a comment beside the test.

**Acceptance criteria.**
- [x] `cargo test -p ethernal-secretfile` passes standalone.
- [x] `cargo tree -p ethernal-secretfile --edges normal` shows exactly `zeroize` and `thiserror`
      (M-4). `rg -n 'clap' crates/ethernal-secretfile/` returns nothing.
- [x] File policy asserted: a **directory** → `IsDirectory` (not an io read error) · a nonexistent
      path → `NotFound` · mode `0000` → `PermissionDenied` · a 4096-byte regular file succeeds and
      a 4097-byte one → `TooLarge` · a **symlink is followed and the target's mode is what is
      checked** (FR-15, the Kubernetes shape).
- [x] `/dev/zero` → `TooLarge` **via the read cap**. The test carries a comment stating it must
      fail if the cap is ever made stat-based (R4 M-a).
- [x] Warning: a 0644 regular file emits **exactly one** line into an injected `Vec<u8>` sink
      containing both `file permissions` and `0644`; a 0600 file emits **none**; a **mode-0440
      FIFO emits none** (R4 M-e — this pins FR-17's regular-file scoping, without which the
      recommended `<(...)` pattern warns on every run).
- [x] `rg -n 'fs::read|read_to_string|read_to_end|\.push\(|\.extend' crates/ethernal-secretfile/src`
      returns nothing on the buffer path (FR-23 — one allocation, never grown).
- [x] `git diff --name-only` touches only `crates/ethernal-secretfile/**` (and `Cargo.lock`).
- [x] `make lint && make test` green.

**Out of scope.** No byte rule, no UTF-8 validation, no public reader (F1-2). No `FileSource`
(F2-1). Nothing under `bins/`.

## [F1-2] The UTF-8 boundary and the two byte rules

**Points:** 2 · **Depends on:** F1-1 · **Discharges:** FR-7, FR-8, FR-9, FR-10, FR-12b

**Description.** The two public entry points — `read_secret_line` (passphrase rule) and
`read_secret_trimmed` (hex rule) — plus the UTF-8 validation that makes all three passphrase
consumers fail closed (D-3). This is the issue that decides which bytes are the secret.

**Implementation notes.**

1. **UTF-8 without residue** (architecture §2.3):
   ```rust
   std::str::from_utf8(&buf).map_err(|_| SecretFileError::NotUtf8 { .. })?;  // borrow, no move
   let owned = std::mem::take(&mut *buf);                                     // move on success only
   Zeroizing::new(String::from_utf8(owned).expect("validated on the line above"))
   ```
   The borrow-check first is **not** redundant: `String::from_utf8` returns `FromUtf8Error`, which
   owns the plain `Vec<u8>` and drops it un-zeroized.
2. **`read_secret_line` — FR-8 then FR-9**, in that order:
   `strip_suffix('\n')` (exactly one, and nothing else) → any residual `'\r'` →
   `LineTerminator { CarriageReturn }` → any residual `'\n'` →
   `LineTerminator { MultiLine { lines: matches + 1 } }`.
3. **`read_secret_trimmed` — FR-7:** `trim_matches(char::is_ascii_whitespace)`. A separate
   entry point rather than a boolean flag (D-2): a parameter is selectable by accident, a
   function name is not.
4. Both rules re-slice in place — no intermediate allocation, so no second copy to scrub.
5. An empty file yields `Ok("")`. **Whether empty is an error is the caller's policy** (FR-18)
   and is deliberately not decided here — architecture §11 divergence 5.

**Acceptance criteria.**
- [ ] `read_secret_line` byte-rule matrix: `pw` and `pw\n` → identical `"pw"` · `"pw \n"` →
      `"pw "` (**the trailing space is kept** — FR-11's claim, and it must be a test, not a
      comment) · `pw\r`, `pw\r\n`, `pw\r\r\n` → `LineTerminator { CarriageReturn }` each ·
      `a\nb` → `LineTerminator { MultiLine { lines: 2 } }` · empty → `Ok("")` · a lone `"\n"` →
      `Ok("")`.
- [ ] `read_secret_trimmed`: leading and trailing ASCII whitespace removed, **interior
      untouched**; `" 0x… \n"` and `"0x…"` yield the same string.
- [ ] Non-UTF-8 bytes → `NotUtf8` from **both** entry points.
- [ ] All **seven** `SecretFileError` variants `Display` the path and **no content** (M-3, first
      instance): construct one of each and assert the rendered string contains the path and does
      not contain a distinctive sentinel taken from the file's bytes.
- [ ] The FR-23 grep gate from F1-1 is **re-run and still clean** over the whole crate — F1-2 adds
      the `mem::take` move, and the property is a whole-crate one.
- [ ] Exactly four public items (`MAX_SECRET_FILE_BYTES`, `Residual`, `SecretFileError`, plus the
      two functions); `read_capped` is not `pub`.
- [ ] `git diff --name-only` touches only `crates/ethernal-secretfile/**`.
- [ ] `make lint && make test` green.

**Out of scope.** No caller. No `KeystoreError` / `SignerError` wrapping (F2). No decision about
empty files. Fixing the three-way non-UTF-8 divergence between S-B/S-C/S-D (PRD §5, FR-12b).
