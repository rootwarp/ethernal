## [F4-2] Flip `validator` and `account` to `--passphrase-file` / `--mnemonic-passphrase-file`

**Points:** 2 · **Depends on:** F2-1, F3-1, F3-2, F4-1 · **Discharges:** FR-1, FR-2, FR-3, FR-4,
FR-5, FR-6, FR-18, FR-19b, I-1, I-2

**Description.** The atomic flip for stream A: the flag surface, the config fields, and the four
call sites that construct a passphrase source. This cannot be split further — renaming
`MnemonicPassphraseForm::Env` breaks `shared_args()`, both `_cli.rs` modules and both `_cmd.rs`
modules in one compile unit.

**Implementation notes.**

1. **`bins/ethernal/src/keystore_cli.rs`** — `shared_args()` (`:61`): the `-env` args are
   **removed, not aliased** (FR-1), replaced by `--passphrase-file` / `--mnemonic-passphrase-file`
   with `value_name("PATH")`. The `conflicts_with` pairing moves with the id rename (`:87`,
   `:97`); the four-form matrix is otherwise identical (FR-3).
2. `MnemonicPassphraseForm::Env { var, value }` → `File { path: String, value: Zeroizing<String> }`
   (FR-4). **The hand-written `Debug` (`:45-58`) stays hand-written** — `Zeroizing` *derives*
   `Debug`, so `#[derive(Debug)]` here would compile and print the secret. Keep `path` visible
   and `value` `[REDACTED]`, exactly as it does for `var` today.
3. `parse_mnemonic_passphrase_form(m: &ArgMatches, warn_out: &mut dyn Write)` gains the sink; the
   caller already has `banner_out` in scope (`validator_cli.rs:192`). Errors map to
   `AppError::exit2(format!("--mnemonic-passphrase-file: {e}"))`.
4. **Config fields:** `passphrase_env: String` → `passphrase_file: Option<PathBuf>` on
   `ValidatorConfig` (`validator_cli.rs:43`) and `AccountConfig` (`account_cli.rs:44`); all six
   `override_usage` strings updated (FR-2); every load path routes the argument through
   `fs_util::secret_file_arg` (FR-6).
5. **The four call sites** — `validator_cmd.rs:94-103`, `:155-164`; `account_cmd.rs:98-108`,
   `:154-164` — swap one constructor, keeping the `MinLenPassphrase` decorator (architecture
   §4.1):
   ```rust
   let keystore_pw: &dyn PassphraseSource = if let Some(p) = &cfg.passphrase_file {
       file_source = FileSource::new(p.clone(), std::io::stderr());
       checked = MinLenPassphrase { inner: &file_source, min: KEYSTORE_PASSPHRASE_MIN_LEN };
       &checked
   } else { tty_pw = NewKeystorePassphrase::new(std::io::stderr()); &tty_pw };
   ```
   **Sizing note:** `validator_cmd.rs` and `account_cmd.rs` hold **zero** `-env` *flag-string*
   occurrences — these are `cfg.passphrase_env` field reads. Sizing them by flag hits under-sizes
   them.
6. **I-2, recorded not fixed.** A comment at the `parse_mnemonic_passphrase_form` warn site
   stating that this warning is erased by `clear_after_ceremony` on `new` and is durable on
   `recover`, citing the identical pre-existing property of the symlinked-output-dir warning
   (`validator_cli.rs:192` / `account_cli.rs:181`). **No hoist, no ceremony change.** Without
   this comment a reviewer files it as a regression — or "fixes" it, which is R-2 exactly.
7. **Test migration:** `validator_e2e.rs` (4), `validator_secret_hygiene.rs` (4),
   `account_secret_hygiene.rs` (4), `exit_usage.rs` (3 — both uses are `validator recover`),
   `account_e2e.rs` (1). All through `common::secret_file`.

**Acceptance criteria.**
- [ ] **I-1:** the passphrase read stays in `finish_from_mnemonic` (`validator_cmd.rs:485`,
      `account_cmd.rs:323`). Review gate: `git diff` contains **no `FileSource::new` above

- [ ] The FR-17 permission case runs on **`recover`** (the `validator_e2e.rs:514` shape), where

## [F4-3] FR-12 — the S-C and S-D byte-rule matrix

**Points:** 1 · **Depends on:** F4-2 · **Discharges:** FR-12 (S-C, S-D), FR-9, FR-10

**Description.** **The only automated evidence that FR-9's widened residual clause is live.**
These rows land here and are **never deferred to F7** (plan §5 rule 5).

**Why S-B cannot substitute.** `normalize_passphrase` strips `\n` and `\r` alike at `u <= 0x1f`
(`crypto.rs:52`), so the S-B row in F5 passes **whether or not FR-8/FR-9 exist**. A suite
carrying only S-B passes under the superseded rule. S-C (v3, raw bytes) and S-D (BIP-39 seed, no
control strip, no trim) are the live checks.

**Implementation notes.**

1. **S-C — `account`, in `bins/ethernal/tests/account_e2e.rs`** (verified: that file already
   imports `ethernal_keystore::decrypt_v3` at `:27`, runs `account recover` with the fixed
   mnemonic over stdin via `run_account_recover` at `:81`, and carries the decrypt round trip at
   `:367`). **Not** `account_secret_hygiene.rs` — that suite asserts absence of leakage, has no
   v3 decrypt path, and an implementer landing the S-C proof there would weaken it to an
   exit-code check, losing the only automated S-C evidence. Extend the existing round-trip
   shape: a passphrase file holding `pw` and one holding `pw\n` produce an **identical, mutually
   decryptable** v3 keystore — `decrypt_v3` the keystore written from one file using the bytes
   of the other.
2. **S-D — `validator recover` with a fixed mnemonic** (`validator_e2e.rs`): `pw` and `pw\n`
   produce an identical **pubkey set**, and both equal the set produced by
   `--mnemonic-passphrase pw`. That third leg is what proves the file path and the raw-value path
   agree.
3. **The three CR rows, on both S-C and S-D:** `pw\r`, `pw\r\n`, `pw\r\r\n` → **exit 2** each,
   six rows total. Write the bytes explicitly; `common::secret_file` adds no terminator of its
   own.
4. Each CR row asserts the message names the **path** and a *shape* ("carriage return"), never
   content (M-3).
5. Keep `--count 1` and the existing fixed mnemonic — these are production-scrypt e2e runs and
   the row count is already six.

**Acceptance criteria.**
- [ ] S-C: `pw` vs `pw\n` → identical v3 keystore, decryptable from **either** file.
- [ ] S-D: `pw` vs `pw\n` → identical pubkey set, **and both equal `--mnemonic-passphrase pw`**.
- [ ] Six CR rows (`pw\r`, `pw\r\n`, `pw\r\r\n` × {S-C, S-D}) each **exit 2**.
- [ ] Each CR assertion carries a comment stating that this row, not S-B, is the evidence FR-9's
      widened clause is live — so a later reader does not delete it as duplicate coverage.
- [ ] No error message in any row contains the passphrase bytes (assert on a distinctive
      sentinel).
- [ ] `make lint && make test` green.

**Out of scope.** S-B (F5-2 — a normalizer regression guard, not byte-rule evidence). The
non-UTF-8 and over-size rows (F7-1). The manual geth round-trip (release gate A5-M).
