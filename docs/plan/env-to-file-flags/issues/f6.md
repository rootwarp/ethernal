## [F6-1] One `LocalSigner`: flip `tx sign` / `tx run` and pass the signer forward

**Points:** 2 · **Depends on:** F2-2, F2-3, F3-1 · **Discharges:** FR-1, FR-2, FR-6, FR-22,
FR-24, FR-25, FR-30, D-4

**Description.** Today `run_action` constructs a `LocalSigner` to derive `from`
(`run_cmd.rs:165`), then hands `private_key_env_var` into `SignConfig` (`:193`) and
`sign_unsigned_tx` constructs a **second** signer (`sign_cmd.rs:174`). The comment at
`run_cmd.rs:162` already admits the key "is read here and again". With a file that second read
is **fatal**: `<(...)` returns zero bytes (R4 M-c), a named FIFO **blocks indefinitely**
(R4 M-d). This cannot be softened into a better error message.

**The fix passes the constructed signer forward — not the material and not the path.**

**Implementation notes.**

1. **One construction site in the binary's local path** (architecture §6.1):
   ```rust
   // sign_cmd.rs — the ONLY LocalSigner construction site.
   pub(crate) fn local_signer_from_file(path: &Path, warn_out: &mut dyn Write)
       -> Result<LocalSigner, AppError>;

   pub fn sign_unsigned_tx(cfg: &SignConfig, local: Option<&LocalSigner>,
       err_writer: &mut dyn Write, unsigned: &UnsignedTx, cancel: &CancelToken)
       -> Result<SignedTx, AppError>;
   ```
   - `("local", Some(s))` → sign with `s` and **do not close it**. `sign_unsigned_tx` closes only
     the signer it constructed itself; closing a borrowed one would zeroize a key the owner still
     holds and make a later `address()` return `SignerClosed`. The **owner** calls
     `let _ = s.close();` right after `sign_unsigned_tx` returns, preserving today's
     prompt-zeroize timing; `LocalSigner: Drop` (`local.rs:240`) is the backstop.
   - `("ledger", _)` → unchanged: construct, sign, `close()`.
   - `("local", None)` → `AppError::Internal`; unreachable, gated by `load_*_config` (FR-24).
2. **`SignConfig.private_key_env_var: String` → `pub private_key_file: Option<PathBuf>`**;
   `RunConfig` the same. **The material never enters either struct** — `Zeroizing<Z>` *derives*
   `Debug` (zeroize 1.9.0 `src/lib.rs:602`), so a `Zeroizing<String>` field would print in full
   under the structs' existing `#[derive(Debug)]` and the compiler would not stop it.
   `Option` because `--signer ledger` legitimately has none.
3. **`run_action` step order**, chosen to preserve today's error precedence:
   ```
   0.  require_ledger_flags_for_rpc(cfg)                      unchanged
   1.  read_input(--input-file)                               unchanged — still first
   1b. if signer == "local" { local = Some(local_signer_from_file(..)?) }
   1c. if local.is_some() && !rpc_url.is_empty() { cfg.build.from = local.address()? }
   2.  build_unsigned_tx                                      unchanged
   3.  optional --keep-unsigned write                         unchanged
   4.  sign_unsigned_tx(&sign_cfg, local.as_ref(), ..)        no second construction
   5.  let _ = local.close()                                  prompt zeroize
   ```
4. `run_action`'s synthetic `SignConfig` (`run_cmd.rs:189-194`) sets **`private_key_file: None`**.
   A live path left there is dead data that invites exactly the second open D-4 exists to
   prevent; **its absence, not a comment, is what structurally forbids one.**
5. **FR-24:** `--private-key-file` is **required** when `--signer local` on both subcommands,
   enforced in `load_sign_config` / `load_run_config` (not by the type). Deliberate UX
   regression — `--private-key-env` has `default_value(DEFAULT_PRIV_KEY_ENV)` today, so
   `ethernal tx sign --signer local` currently works with no key flag at all.
6. **FR-25 deletions:** `DEFAULT_PRIV_KEY_ENV` (`sign_cmd.rs:19`), `is_posix_env_var_name`
   (`sign_cmd.rs:204`) and its `posix_env_var_name_matrix` test.
7. **FR-30:** `--signer` help no longer says "env-var private key" (`sign_cmd.rs:65`,
   `run_cmd.rs:69`); `sign_cmd.rs:46-49`'s `long_about` is restated for a **path** argument.
8. Route both flag values through `fs_util::secret_file_arg` (FR-6). `value_name("PATH")` and
   the `override_usage` strings (FR-2).
9. **Test migration:** `sign.rs`, `run.rs`, `run_rpc.rs`, `e2e_pipeline.rs` (both are
   `--private-key-env`; this file runs no `deposit gen`) and `e2e_live.rs:146`, all through
   `common::secret_file`.

**Acceptance criteria.**
- [x] **Exactly one `LocalSigner` construction site** in the binary's local path:
      `rg -n 'new_local_signer_from_(file|hex|env)' bins/ethernal/src` shows one call in
      `sign_cmd.rs` and none in `run_cmd.rs`.
- [x] **A test asserts `run_action`'s synthetic `SignConfig` has `private_key_file: None`** —
      the structural guard ships in the same issue as the field it guards.
- [x] `SignConfig` / `RunConfig` hold `Option<PathBuf>` and no secret material; a `Debug`
      rendering of a populated `SignConfig` contains the path and no key bytes.
- [x] **R-4:** `run::invalid_input` (exit 2), `run::bad_key` (exit **3**) and
      `sign::invalid_input_json` (exit 2) pass **unmodified** — verified by `git diff` showing no
      change to those test bodies.
- [x] FR-24: `tx sign --signer local` and `tx run --signer local` with **no key flag** each exit
      2 naming `--private-key-file`.
- [x] `--private-key-file -` exits 2 (FR-6).
- [x] `rg -n 'DEFAULT_PRIV_KEY_ENV|is_posix_env_var_name|posix_env_var_name_matrix' bins/`
      returns zero (FR-25).
- [x] `rg -n 'env-var private key' bins/` returns zero; `tx sign --help`'s `long_about` describes
      a path argument (FR-30).
- [x] `rg -n -- '--private-key-env' bins/` returns zero.
- [x] `make lint && make test`, `make e2e-mock` green, **and `make e2e-live` re-run locally**
      (R-8).

**Out of scope.** The FIFO / RPC read-once evidence (F6-2). The FR-19 hex guard and the
allowlist (F6-3). `exit_usage.rs`'s unknown-flag cases (F7-3).

## [F6-2] FR-33 / R-5 — read-once evidence in **RPC mode**, and the exit-2 divergence

**Points:** 1 · **Depends on:** F6-1 · **Discharges:** FR-22 (evidence), FR-33, architecture §11
divergence 4

**Description.** The two-signer path is gated on `cfg.signer == "local" && !cfg.build.rpc_url
.is_empty()` (`run_cmd.rs:164`). **A test without `--rpc-url` passes vacuously** — it exercises
the one path that only ever constructed one signer (R-5). Plus the one behavior change in this
phase that no existing test pins.

**Implementation notes.**

1. **Both read-once rows run `tx run --signer local --rpc-url <stub>`**, in `run_rpc.rs` beside
   the existing stub-RPC cases:
   - `--private-key-file <(printf '%s' KEY)` **succeeds**.
   - the same run with a named `mkfifo` FIFO **completes**, under an explicit wall-clock deadline
     — the measured failure is an indefinite block, not an error (R4 M-d), so the test must kill
     and fail rather than hang CI. Create the FIFO by shelling out to `mkfifo` (no new
     dependency) and start the writer before the run.
2. **Each test carries a comment stating that RPC mode is required** and what reverting the
   read-once fix would break. Without it the next reader "simplifies" the test by dropping
   `--rpc-url` and it silently stops testing anything.
3. **Architecture §11 divergence 4 needs its own evidence:** a **missing or unreadable**
   `--private-key-file` exits **2**, where a missing env var exits **3** today. No existing test
   pins the old behavior, so this is an unpinned behavior change. Assert it as a named test, on
   both `tx sign` and `tx run`, and assert the message names the path.

**Acceptance criteria.**
- [x] `tx run --signer local --rpc-url <stub> --private-key-file <(printf '%s' KEY)` succeeds.
- [x] The same RPC-mode run with a named FIFO **completes** under a wall-clock deadline.
- [x] Both tests are in **RPC mode** and say so in a comment; a reviewer can see the assertion
      would pass vacuously without `--rpc-url`.
- [x] A missing `--private-key-file` exits **2** (not 3) on both `tx sign` and `tx run`, with the
      path named and no file contents in the message.
- [x] A permission-denied key file exits **2** on both subcommands.
- [x] `make lint && make test`, `make e2e-mock` green; `make e2e-live` re-run locally if the
      issue touches `e2e_live.rs`.

**Out of scope.** The `deposit gen` FIFO test (F5-2 — different code path, different gate). The
hygiene sweep (F7).

## [F6-3] FR-19 hex-shaped-argument guard + FR-35 harness allowlist

**Points:** 1 · **Depends on:** F6-1 · **Discharges:** FR-19, FR-32, FR-35, D-8

**Description.** `is_posix_env_var_name` was a footgun guard: it caught an operator passing a
*value* where a *name* was expected. The same mistake is now passing a **key** where a **path**
is expected, and it is worse — the not-found error would echo the argument, which is the secret.

**Implementation notes.**

1. In `local_signer_from_file`, on the **`SecretFileError::NotFound` branch only** (D-8): test the
   argument against `^(0x)?[0-9a-fA-F]{64}$` and, on a match, replace the error with exit 2
   naming the flag and the mistake — **without echoing the argument**. Never a pre-flight `stat`:
   there is still exactly **one `open` per invocation**.
2. **FR-35:** remove `ETHERNAL_TX_PRIVATE_KEY` from `ETHERNAL_ENV_VARS`
   (`bins/ethernal/tests/common/mod.rs:54` — verified; architecture §9 cites `:53`) — there is
   no secret in the environment to scrub
   any more. **`ETHERNAL_TX_RPC_URL` / `_FROM` / `_GAS_LIMIT` stay** (OD-1, A-1): they take
   values, not variable names, and hold no secrets. Line-disjoint from F3-1's helper in the same
   file.

**Acceptance criteria.**
- [ ] `--private-key-file 0x<64 hex>` exits 2 with a message containing "looks like a key value,
      not a path" (or the shipped equivalent wording), on both `tx sign` and `tx run`.
- [ ] **FR-32:** the rejected argument appears in **neither stdout nor stderr** — the assertion
      scans the full output for the hex string, and the hex string is a distinctive sentinel so
      the assertion is not satisfied by empty output.
- [ ] The same 64-hex argument naming a file that **does exist** is read as a path, not rejected
      — the guard is on the `NotFound` branch only.
- [ ] A 63-char and a 65-char hex-ish argument fall through to the ordinary `NotFound` message
      (the guard is exact-length).
- [ ] `ETHERNAL_TX_PRIVATE_KEY` is gone from `ETHERNAL_ENV_VARS`; `_RPC_URL`, `_FROM` and
      `_GAS_LIMIT` remain, asserted by a `rg` over `common/mod.rs` in the review.
- [ ] `make lint && make test` green with **no existing assertion modified**.

**Out of scope.** `exit_usage.rs` cases (F7-3). Any change to the `ETHERNAL_TX_*` value fallbacks
themselves (out of scope by A-1, plan §5 rule 8).
