## [F7-1] The eight error paths in the two hygiene suites

**Points:** 1 · **Depends on:** F4-2, F4-3 · **Discharges:** FR-31

**Description.** Assert, per error path, the **exit code** and the **absence of file contents**
in stdout, stderr, the log stream and any `Debug` rendering (M-3).

**The eight rows are architecture §9's list, which is not FR-31's.** §9 **replaced** FR-31's
"bad hex" and "wrong passphrase" rows with the **CR** and **non-UTF-8** rows. Record the reason
in the test module, or a later reader will restore the PRD's list from the requirement ID: the
two dropped rows are pre-existing paths with no new file-mode leak vector and are already
covered; the two added rows are **new failure modes the file source creates**.

**Implementation notes.**

1. In `bins/ethernal/tests/validator_secret_hygiene.rs` and
   `bins/ethernal/tests/account_secret_hygiene.rs`, one case per row:

   | Row | Expected |
   |---|---|
   | not found | exit 2, path named |
   | permission denied (mode `0000`) | exit 2 |
   | is-a-directory | exit 2, **FR-14's intended message, not `Is a directory (os error 21)`** |
   | empty (`--passphrase-file`) | exit 2 |
   | multi-line | exit 2, a **line count**, never content |
   | CR (`pw\r` / `pw\r\n` / `pw\r\r\n`) | exit 2, "carriage return", never content |
   | over-size (4097 bytes, and `/dev/zero`) | exit 2, **never truncated** |
   | non-UTF-8 | exit 2 |

2. Every fixture goes through `common::secret_file`; the mode-`0000` and directory cases set
   their own mode after the helper returns.
3. The mode-`0000` case does not hold when the suite runs as **root** — note it beside the test.
4. `--passphrase-file /dev/zero` is one of the over-size rows and must be `#[cfg(unix)]`.

**Acceptance criteria.**
- [ ] All eight rows present in **both** files, each asserting exit code **and**
      `!output.contains(sentinel)` over stdout, stderr and the log stream.
- [ ] The directory row asserts the FR-14 message text and asserts the raw OS string
      `Is a directory (os error 21)` is **absent**.
- [ ] `--passphrase-file /dev/zero` exits 2.
- [ ] The over-size row uses a 4097-byte file whose content is a repeated sentinel, and asserts
      the sentinel does not appear in any output.
- [ ] A comment in each file records why the row list differs from FR-31's (architecture §9's
      substitution, with the reason).
- [ ] `make lint && make test` green with **no existing assertion modified**.

**Out of scope.** `redact_boundary.rs` (F7-2). `exit_usage.rs` and help text (F7-3).

## [F7-2] `redact_boundary.rs` — `Debug` and log-stream leak assertions

**Points:** 1 · **Depends on:** F4-2, F6-1 · **Discharges:** FR-31 (`Debug`/log half), M-3

**Description.** **`bins/ethernal/tests/redact_boundary.rs` contains zero `-env` flag occurrences
and is real work here.** It is sized by the **new** FR-31 assertions — the `Debug` and structured
-log surfaces that the env path never had a file-contents leak vector for — not by flag hits.

**Implementation notes.**

1. **What this file is** (verified from its own header): an *end-to-end* boundary contract —
   it drives the real binary and asserts stderr never contains the embedded secret while it
   *does* contain the safe reduced form. Its three existing tests
   (`build_rpc_error_url_redacted_path_key`, `…_query_key`, `send_rpc_error_url_redacted`) are
   about RPC-URL redaction. **The new work extends the same contract to secret-file errors:
   the message carries the path, never the bytes.**
2. Two leak surfaces are new with a file source, and both are the reason FR-31 says "extended,
   not renamed":
   - an error that echoes file **contents** — every `SecretFileError` variant must render the
     **path** and never the bytes (the crate-level guarantee from F1-2, re-asserted here through
     the real binary);
   - a **not-found** error that echoes an argument the operator may have mistakenly made the
     secret (F6-3's guard, asserted here across commands).
3. **The structured-log row is `deposit gen` only.** Verified: `--json-logs` is defined at
   `gen_cli.rs:146` and **nowhere else** — `validator`, `account` and `tx` have no structured-log
   flag (a `--json-logs` for validator is deferred by the keygen plan, X4). Do not write a
   log-stream criterion for those namespaces; it is unsatisfiable.
4. **Config `Debug` renderings are asserted where they live, not here.**
   `MnemonicPassphraseForm::File` is F4-2's criterion and `SignConfig` / `RunConfig` are F6-1's,
   both as `#[cfg(test)]` unit assertions in `src/`. This issue covers the *observable* surface:
   what the binary actually prints.

**Acceptance criteria.**
- [ ] One secret-file failure case per namespace — `validator`, `account`, `deposit gen`,
      `tx sign` — driving the real binary and asserting stderr contains the **path** and **not**
      the sentinel, on both stdout and stderr.
- [ ] The `deposit gen --json-logs` run over a failing secret-file case emits a log stream
      containing the path and not the sentinel. **This row is `deposit gen` only** — a comment
      records that no other namespace has a structured-log flag.
- [ ] Every sentinel is distinctive enough that an empty output cannot satisfy the assertion, and
      each test asserts the output is **non-empty** before asserting the absence.
- [ ] A file whose bytes are hex-shaped and whose path does not exist is rejected without the
      argument appearing in output (FR-32's cross-command leg; the guard itself is F6-3's).
- [ ] `make lint && make test` green with **no existing assertion modified** — the three existing
      RPC-URL tests are untouched.

**Out of scope.** The per-path exit codes (F7-1). Fixing the three-way non-UTF-8 divergence (PRD
§5).

## [F7-3] `exit_usage.rs` cases + repointed help-text assertions

**Points:** 1 · **Depends on:** F4-2, F5-1, F6-1 · **Discharges:** FR-34, FR-1, FR-2

**Description.** Prove the removed flags are **unknown flags** and that no help-text assertion
still requires a name that no longer exists.

**Implementation notes.**

1. `bins/ethernal/tests/exit_usage.rs` gains **one case per new exit-2 path** and asserts each of
   the three removed flags — `--passphrase-env`, `--mnemonic-passphrase-env`,
   `--private-key-env` — is now an **unknown flag** (clap exit 2, FR-1/FR-34) on every command
   that used to accept it.
2. Repoint the help-text assertions to the new names —
   `bins/ethernal/tests/validator_e2e.rs:440-443`'s `help.contains("--mnemonic-passphrase-env")`
   **and its siblings**. Find them with
   `rg -n 'help\.contains|--help' bins/ethernal/tests` rather than assuming the inventory is
   complete; they fail on FR-2 otherwise.
3. This is **repointing, not loosening** (plan §5 rule 6): each assertion still requires an exact
   flag name, the new one.

**Acceptance criteria.**
- [ ] Each of the three removed flags exits 2 as an unknown flag on every command that previously
      accepted it, asserted per command.
- [ ] One `exit_usage.rs` case per new exit-2 path introduced by this change (missing required
      `--private-key-file`; `-` as a value; empty `--passphrase-file`).
- [ ] Every `help.contains("--…-env")` assertion in the suite is repointed to the new name;
      `rg -n -- '--(passphrase|private-key|mnemonic-passphrase)-env' bins/ethernal/tests` returns
      zero. (Use the PRD's own pattern — a bare `-env` also matches `.env(` calls and `_env`
      identifiers that legitimately remain, e.g. the `ETHERNAL_TX_RPC_URL` fallback tests.)
- [ ] No help-text assertion is weakened from an exact name to a substring of a shorter prefix.
- [ ] `make lint && make test` green.

**Out of scope.** The doc sweep (F8-2) — `rg` over `docs/` is F8's, and it runs after this phase.
