# Phase M0.4 — Trust Boundary 1: Withdrawal-Credential Input + `Redact` Helper

**Objective.** Close GO-001 (the critical fund-loss bug) by removing `defaultWithdrawalCreds()` and enforcing the withdrawal-credential input boundary at two layers (CLI flag + `Entry.Validate` DiD). Ship the shared `Redact` helper as part of this phase because every downstream secret-leak fix consumes it.

**Dependencies.** M0.1 (lint), M0.3 (range constants co-located cleanly with atomicio; not a hard dep).

**Exit criteria recap (project-plan §M0.4).**
- `--withdrawal-address` flag validates EIP-55 checksum, length, hex.
- `defaultWithdrawalCreds` symbol grep-clean.
- `Entry.Validate` and `tx.Validate` table-driven tests cover every rejection class.
- `Redact("0xabcdef...", 4)` returns `"0xab... (len=N)"`.
- Existing golden tests skipped with tracking marker until M0.10.
- `make assert-no-zero-wc` target exists (activated in M0.10).

**Locked decision.** v0.2 is **0x01-only** (`--withdrawal-address`); no `--withdrawal-bls-pubkey`. 0x00/0x02 are vNext candidates.

**Phase totals.** 10 issues, 16 points (~8 days single-stream).

## Issue M0.4-4 — `Entry.Validate` WC shape checks + sentinels (DiD)

- **Points:** 3
- **Priority:** P0
- **Closes:** FR-P0-A2 (GO-001 DiD) — `internal/deposit` layer
- **Depends on:** M0.4-1 (sentinel infrastructure)

**Description.** Add to `Entry.Validate` (file `internal/deposit/json.go:137-154`) the WC shape checks:
(a) reject `0x00` prefix with all-zero body → `ErrZeroWithdrawal00`.
(b) reject `0x01`/`0x02` prefix where bytes 1..11 non-zero → `ErrInvalidWCFormat`.
(c) reject all other prefixes → `ErrInvalidWCFormat`.

**Implementation notes.**
- New sentinels in `internal/deposit/errors.go` per architecture §15:
  - `var ErrZeroWithdrawal00 = errors.New("withdrawal_credentials with 0x00 prefix has all-zero body")`
  - `var ErrInvalidWCFormat = errors.New("withdrawal_credentials format invalid for prefix")`
- Per architecture §7.2 boundary table: both sentinels → exit code 2.
- These checks are DiD; the CLI flag (M0.4-1) is the first layer. They must run on the read path so a hand-crafted JSON entry that bypasses the flag is still rejected.

**Acceptance criteria.**
- [ ] Table-driven `TestEntry_Validate_WC_Reject` covers: all-zero 0x00; 0x01 with non-zero byte 1; 0x01 with non-zero byte 11; 0x02 with non-zero byte 5; 0xff prefix.
- [ ] `TestEntry_Validate_WC_Accept` confirms canonical 0x01 layout (0x01 || 0x00*11 || addr) passes.
- [ ] Each rejection wraps the expected sentinel (verified via `errors.Is`).
