# Phase M0.5 — Trust Boundary 2: Network/Fork Binding + Read-Path Verification

**Objective.** Close GO-002 (the second critical/high finding) by binding deposit-data network/fork-version to the build target at two layers; close GO-012 by recomputing SSZ roots and BLS-verifying the signature on the read path.

**Dependencies.** M0.2 (geth APIs), M0.4 (sentinel infrastructure + WC checks live in the same `Entry.Validate`).

**Exit criteria recap (project-plan §M0.5).**
- Cross-network signing test: hoodi data fed to `--network mainnet` → exit 2 with `ErrNetworkMismatch`.
- Fork-version mismatch test: hand-tampered `fork_version` → exit 2.
- SSZ-root tamper test: mutate `signature` → root mismatch → exit 2.
- BLS-signature tamper test: flip a byte → `ErrBLSSignatureInvalid` exit 3.
- Pubkey-at-infinity rejected (M0 acceptance; M1 hardens further).

**Phase totals.** 6 issues, 15 points (~7.5 days single-stream).

## Issue M0.5-1 — `Entry.ValidateForNetwork(target, v)` + sentinels (split-watch)

- **Points:** 4
- **Priority:** P0
- **Closes:** FR-P0-A3 (GO-002), partial FR-P0-A4 (GO-012)
- **Depends on:** M0.4-4

**Description.** New method `Entry.ValidateForNetwork(target network.Params, v bls.Verifier) error` on `internal/deposit.Entry` per architecture §15 and ADR-002. Enforces:
- `entry.NetworkName == target.Name` → `ErrNetworkMismatch`
- `entry.ForkVersion == target.GenesisForkVersion` → `ErrForkVersionMismatch`
- `bls.ValidatePubkeyBytes(entry.Pubkey)` → `bls.ErrPubkeyInvalid` (identity-check hardened in M1.2-2)
- BLS signature verifies vs `compute_domain(DOMAIN_DEPOSIT, target.GenesisForkVersion, ZeroGenesisValidatorsRoot)` → `ErrBLSSignatureInvalid` (exit 3 per architecture §15)

**Implementation notes.**
- File: `internal/deposit/json.go` (next to `Entry.Validate`).
- Sentinels: `ErrNetworkMismatch`, `ErrForkVersionMismatch`, `ErrBLSSignatureInvalid` — per architecture §6.6 / §15.
- Verifier is injected (`bls.Verifier`) so callers can pass `bls.DefaultVerifier()`; do NOT construct verifier inside the method (ADR-002 keeps deposit's deps clean).
- Domain computation: reuse `ssz.ComputeDomain` (existing) with `network.DomainDeposit()` (the function form lands in M1.2-3; for M0 it remains a package var, which is fine).
- **Split-watch:** if BLS verifier wiring through call sites adds >3 hr, split the call-site activation into a separate issue (M0.5-5 already covers wire-up; if `cfg`-passing requires reshaping `BuildConfig`, separate that out).

**Acceptance criteria.**
- [x] `TestValidateForNetwork_NetworkMismatch`: hoodi entry vs mainnet params → `ErrNetworkMismatch`.
- [x] `TestValidateForNetwork_ForkVersionMismatch`: tampered fork_version → `ErrForkVersionMismatch`.
- [x] `TestValidateForNetwork_BadBLSSig`: byte-flip in signature → `ErrBLSSignatureInvalid` exit 3.
- [x] `TestValidateForNetwork_HappyPath`: well-formed hoodi entry vs hoodi params → nil.
- [x] All 5 sentinels declared in `internal/deposit/errors.go` with package-level `errors.New`.
