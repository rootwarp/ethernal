# Phase M1.4 — Keystore Correctness

**Objective.** Close FR-P1-E — every keystore loader path becomes tightly typed and bounded.

**Dependencies.** M0.11.

**Exit criteria recap (project-plan §M1.4).**
- Table-driven test: each rejection class returns its sentinel; exit codes per architecture §15.
- FIFO/symlink/device-file in scan dir → skipped + warning logged.
- 2 MiB pseudo-keystore → `io.ErrUnexpectedEOF` or LimitReader bound exceeded → rejected.
- Short-secret (31 bytes after decrypt) → `ErrKeystoreMalformed`; secret bytes zeroed.

**Phase totals.** 4 issues, 9 points (~4.5 days single-stream).

## Issue M1.4-4 — `IsRegular()` filter + `io.LimitReader` 1 MiB cap

- **Points:** 2
- **Priority:** P1
- **Closes:** FR-P1-E4 (GO-030)

**Description.** Per architecture §6.4: `ScanDir` skips entries where `!e.Type().IsRegular()` (rejecting FIFOs/devices/symlinks). Both `ScanDir` and `Load` wrap reads in `io.LimitReader` with `MaxKeystoreSize = 1 << 20` (1 MiB) per architecture §15.

**Implementation notes.**
- File: `internal/keystore/scandir.go:54-66`, `internal/keystore/keystore.go:100`.
- `const MaxKeystoreSize = 1 << 20` exported per architecture §15.
- Skips logged via the M1.4-2 logger at WARN.

**Acceptance criteria.**
- [ ] `TestScanDir_Symlink_Skipped`: symlink in dir → skipped + WARN logged.
- [ ] `TestScanDir_FIFO_Skipped` (Unix-only, mocked).
- [ ] `TestLoad_2MiBFile_Reject`: file > MaxKeystoreSize → LimitReader bound exceeded → rejected with descriptive error.
