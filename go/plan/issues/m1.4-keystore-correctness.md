# Phase M1.4 — Keystore Correctness

**Objective.** Close FR-P1-E — every keystore loader path becomes tightly typed and bounded.

**Dependencies.** M0.11.

**Exit criteria recap (project-plan §M1.4).**
- Table-driven test: each rejection class returns its sentinel; exit codes per architecture §15.
- FIFO/symlink/device-file in scan dir → skipped + warning logged.
- 2 MiB pseudo-keystore → `io.ErrUnexpectedEOF` or LimitReader bound exceeded → rejected.
- Short-secret (31 bytes after decrypt) → `ErrKeystoreMalformed`; secret bytes zeroed.

**Phase totals.** 4 issues, 9 points (~4.5 days single-stream).

## Issue M1.4-1 — Structural-vs-checksum error classification + `ErrKeystoreCipherText`

- **Points:** 3
- **Priority:** P1
- **Closes:** FR-P1-E1 (GO-025)
- **Depends on:** —

**Description.** Per architecture §6.4 / §15: pre-validate keystorev4 JSON shape; only the checksum mismatch maps to `ErrWrongPassphrase`. Structural failures map to `ErrKeystoreMalformed` (existing) or new `ErrKeystoreCipherText`.

**Implementation notes.**
- File: `internal/keystore/keystore.go` (Load function).
- New sentinel: `var ErrKeystoreCipherText = errors.New("keystore cipher text invalid")` per architecture §15.
- Per architecture §8.2 rule 1: do NOT `%w` the decoder error if it might embed secret material — use the fixed sentinel.
- Exit code 2 for both `ErrKeystoreMalformed` and `ErrKeystoreCipherText` per architecture §15 table.

**Acceptance criteria.**
- [x] `TestLoad_StructuralMissingField_ErrKeystoreMalformed`: missing JSON field → `ErrKeystoreMalformed`.
- [x] `TestLoad_StructuralBadCipherText_ErrKeystoreCipherText`.
- [x] `TestLoad_ChecksumMismatch_ErrWrongPassphrase`: bad passphrase only → `ErrWrongPassphrase`.
- [x] Error string does not contain any keystore payload bytes (regression).

**Status:** fixed
**Response:** Added `var ErrKeystoreCipherText = errors.New("keystore cipher text invalid")` (in keystore.go per impl note). Updated Load() decrypt path to map only exact "invalid checksum" (from wealdtech) to ErrWrongPassphrase (preserving existing %w: %v pattern); all other decrypt structural errors (no checksum, no cipher, unsupported KDF, invalid IV, bad hex etc) return fixed `%w: path` of ErrKeystoreCipherText sentinel (no decoder err %w'ed, per arch §8.2 rule 1). Top-level structural (missing field, bad JSON, missing crypto) remain/ map to ErrKeystoreMalformed. Updated Load godoc error table. Added precisely the 4 AC tests (3 named TestLoad_* plus one for regression AC) following exact style of existing error tests (e.g. TestLoad_MissingCryptoField, TestLoad_WrongPassphrase, use of writeFixture/generateFixture, errors.Is checks, t.Fatal/t.Errorf). Regression asserted by grepping distinctive hex fragments from the constructed bad-cipher JSON out of err.Error(). No payload bytes possible because sentinel is fixed string (no raw, no %v of potentially-leaky err). Zeroize of pw still happens via existing defer on error paths. Did not touch cmd/ (smallest change; exit-2 recognition of new sentinel per arch §15 table is exercised via errors.Is in M1.5 TestExitCodeContract; keystore package tests only per verification spec). gofmt/go vet/test green.

## Implementation Summary (M1.4-1 only)

**Files changed:**
- `go/internal/keystore/keystore.go` (sentinel + Load logic + doc)
- `go/internal/keystore/keystore_test.go` (exactly 4 new AC tests)
- `go/plan/issues/m1.4-keystore-correctness.md` (status + response + this summary)

**Key decisions (smallest change, exact patterns):**
- Placed new sentinel in `keystore.go` (with other ErrKeystore* ; no separate errors.go existed).
- Classification happens only at the Decrypt site (pre-existing crypto!=nil catches some Malformed early). Used exact == "invalid checksum" to identify the sole WrongPassphrase case (from wealdtech decrypt.go analysis); all else fixed sentinel. No new imports, no pre-pw inner checks (would not be smallest), no %w on any decrypt err for cipher case.
- Error wrapping for CipherText: `fmt.Errorf("%w: %s", Err..., path)` — consistent with nearby Malformed/Version patterns, guarantees no payload bytes in string, errors.Is works.
- Tests: individual funcs (not table) to match existing Load error tests style exactly (no new helpers, reuse writeFixture etc, context.Background, newBytesSource, t.Fatal for nil-err, t.Errorf for Is). 4th AC covered by dedicated leak test (and inline asserts).
- Did not implement other M1.4 issues, did not edit cmd/eth-deposit-gen (even though exitCodeFor and its table will need update for full contract; verification scoped to keystore pkg only; sentinel addition is sufficient for errors.Is in future).
- No zeroize changes here (M1.4-3); pw defer already protects bad paths. No features added.
- Followed CONVENTIONS.md (gofmt, error style, doc, test names), architecture §8.2/§15/§6.4, M0.8/M1.1/M1.3 patterns (fixed sentinels, no secret in errs).

**What was implemented (how ACs met):**
- AC1: TestLoad_StructuralMissingField_ErrKeystoreMalformed added; exercises missing top-level field → ErrKeystoreMalformed (via existing pre-decrypt path).
- AC2: TestLoad_StructuralBadCipherText_ErrKeystoreCipherText added; constructs crypto lacking "checksum" key (triggers lib "no checksum" structural) → ErrKeystoreCipherText even with correct pw.
- AC3: TestLoad_ChecksumMismatch_ErrWrongPassphrase added; bad-pw on good fixture → ErrWrongPassphrase (and explicitly not Is CipherText).
- AC4: TestLoad_ErrString_DoesNotContainKeystorePayloadBytes (plus asserts inside AC2 test) constructs bad-cipher JSON containing distinctive hex fragments (cipher message, pubkey) and asserts none appear in err.Error() for the returned error. Fixed sentinel ensures this by design (regression guard).
