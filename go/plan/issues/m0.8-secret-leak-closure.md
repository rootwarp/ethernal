## Issue M0.8-4 — `CachingPromptSource` (single TTY prompt across workers)

- **Points:** 3
- **Priority:** P0
- **Closes:** FR-P0-C5 (GO-007)
- **Depends on:** —

**Description.** Implement `internal/keystore.CachingPromptSource` per architecture §9.1, §6.4, §15. Wraps any `PassphraseSource`; `sync.Once` first read blocks; subsequent reads return per-call copies; `Zeroize()` wipes the cache at end of run.

**Implementation notes.**
- File: new `internal/keystore/passphrase_cache.go`.
- API per architecture §15:
  - `func NewCachingPromptSource(inner PassphraseSource) *CachingPromptSource`
  - `func (c *CachingPromptSource) Read() ([]byte, error)`
  - `func (c *CachingPromptSource) Zeroize()`
- Per-call `Read` must return a fresh `make([]byte, len(cached))` + `copy` so the loader's `defer zeroizeBytes` doesn't clobber the cache.
- `runWithDeps` (in `cmd/eth-deposit-gen/main.go`) wraps `termPromptSource` when no env source is configured; calls `c.Zeroize()` regardless of outcome (defer).
- Existing `termPromptSource.Read()` becomes mutex-guarded against itself (architecture §6.4 concurrency contract).

**Acceptance criteria.**
- [ ] `TestCachingPromptSource_OncePromptAcrossWorkers` (`-race`): 8-worker pool reads → underlying source invoked exactly once.
- [ ] `TestTermPromptSource_RaceParallelRead` (`-race`): concurrent reads of `termPromptSource` do not race on termios.
- [ ] `TestCachingPromptSource_Zeroize`: post-Zeroize, internal byte slice is zeroed (verify via reflect or test-only accessor).
- [ ] `-race` clean under `go test -race -count=10`.
