## Issue M1.1-1 — Worker `ctx.Err()` per-iteration check + loader honours ctx

- **Points:** 3
- **Priority:** P1
- **Closes:** FR-P1-B1 (GO-008) — worker portion
- **Depends on:** —

**Description.** Per architecture §9.2: at the top of the `for i := range work` loop in `cmd/eth-deposit-gen/main.go:298-368`, check `workerCtx.Err()`; if non-nil emit a `workerResult{idx: i, err: ctx.Err()}` and `continue` so the collector receives exactly one result per work item. Make `keystore.KeyLoader.Load` honour ctx: check `ctx.Err()` before file read, before `pw.Read()`, before `Decrypt`.

**Implementation notes.**
- Files: `cmd/eth-deposit-gen/main.go:298-368` (worker pool), `internal/keystore/loader.go` (Load impl).
- `Decrypt` itself (scrypt) cannot be cancelled mid-flight — only at boundaries. Document this in the loader's Load comment.
- Per-iteration ctx check guarantees the collector's `for r := range results` invariant.

**Acceptance criteria.**
- [ ] `TestWorkerPool_CtxCancelMidRun_AllWorkersEmitOneResult`: cancel ctx mid-run → exactly N results (where N = work count).
- [ ] `TestLoader_CtxCancelBeforeRead_NoFileIO`: cancel before Load → no file I/O attempted.

## Issue M1.1-2 — SIGTERM via `signal.NotifyContext` + second-Ctrl+C force-terminate

- **Points:** 2
- **Priority:** P1
- **Closes:** FR-P1-B1 (GO-008) — signal portion

**Description.** Per architecture §9.2 and §9.4: register SIGTERM in addition to SIGINT via `signal.NotifyContext(ctx, syscall.SIGINT, syscall.SIGTERM)` in both CLIs. - The `stop()` function returned by `NotifyContext` un-registers the trap.
- Test: send SIGINT once → ctx.Done(); send second SIGINT → process exits via default handler.

**Acceptance criteria.**
- [ ] `TestWorkerPool_SIGINTPropagatesWithin1s`: SIGINT during a queued prompt aborts within 1 s without re-prompting remaining workers.
- [ ] `TestSIGTERM_CleanShutdown`: SIGTERM mid-flight → ctx.Done() fires; cleanup runs.
- [ ] `TestSecondCtrlC_ForceTerminate`: first SIGINT cancels; second exits with default handler (verified via subprocess test).

## Issue M1.1-3 — `LocalSigner.mu sync.Mutex` + race tests

- **Points:** 3
- **Priority:** P1
- **Closes:** FR-P1-B2 (GO-021)
- **Depends on:** —

**Description.** Per architecture §9.3: add `LocalSigner.mu sync.Mutex` guarding `key` and `closed` together. `Sign` acquires mu, checks closed, copies key to local var, releases mu, then signs off-lock. `Close` acquires mu and zeroes key then sets closed.

**Implementation notes.**
- File: `internal/signer/local.go:74,100,144-152`.
- `Sign` does signing work OFF lock to keep it fast (avoid serializing all `Sign` calls).
- `closed` remains `atomic.Bool` for the fast-path read, but the write path now goes through the mutex (so the invariant "key is non-nil iff closed is false" holds).

**Acceptance criteria.**
- [ ] `TestLocalSigner_RaceSignClose -race -count=100`: 100 concurrent Sign+Close pairs, no race detected.
- [ ] `TestLocalSigner_SignAfterClose` returns `ErrSignerClosed`.
- [ ] Existing happy-path test still green.

## Issue M1.1-4 — `LedgerSigner.Close` bounded 30s timeout + stderr message

- **Points:** 2
- **Priority:** P1
- **Closes:** FR-P1-B3 (GO-024)
- **Depends on:** —

**Description.** Per architecture §9.5: when `Close` is called with `ctx.Err() != nil`, emit `"reject on device to unblock"` to stderr. Add a 30 s bounded timeout (configurable) after which Close returns with a logged warning; the goroutine waiting on `wallet.SignTx` is leaked (unavoidable per research/03 §1: geth `wallet.SignTx` cannot be interrupted mid-APDU).

**Implementation notes.**
- File: `internal/signer/ledger.go` (`LedgerSigner.Close`).
- Timeout default 30 s; expose via a constructor option for tests.
- Log warning at WARN level via the injected `*slog.Logger` (or fallback to stderr if not present).

**Acceptance criteria.**
- [ ] `TestLedgerSigner_CloseAfterCancel_StderrMessage` (fake wallet): stderr captured contains `"reject on device to unblock"`.
- [ ] `TestLedgerSigner_CloseTimeout_WarningEmitted` (fake wallet that hangs): after 30 s (compressed via constructor option for tests), warning logged and Close returns.
- [ ] Doc comment on `LedgerSigner.Close` explicit about the goroutine-leak warning.
