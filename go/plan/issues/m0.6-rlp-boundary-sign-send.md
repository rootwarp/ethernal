## Issue M0.6-4 — `validateSignedAgainstRLP` implementation (split-watch)

- **Points:** 4
- **Priority:** P0
- **Closes:** FR-P0-A6 (GO-004) — validator
- **Depends on:** M0.2-1, M0.5-4

**Description.** New helper `validateSignedAgainstRLP(signed *signer.SignedTx, netParams network.Params) (*types.Transaction, error)` per architecture §6.12, §7.3, §15, ADR-003. Lives in `cmd/eth-deposit-tx/send.go` (not in `internal/`, to avoid `signer↔network` cycles).

Decodes `signed.RawRLP` via `types.Transaction.UnmarshalBinary`; enforces:
- `decoded.Type() == DynamicFeeTxType`.
- Recovered sender via `types.Sender(types.LatestSignerForChainID(decoded.ChainId()), decoded)` equals `signed.From`.
- `decoded.ChainId/To/Value/Nonce/Hash` equal JSON metadata.
- `decoded.To` equals `netParams.DepositContractAddress` (unless override).
- Any divergence → `ucli.Exit(... 2)`.

Returns the decoded `*types.Transaction` so callers can render the prompt from decoded values.

**Implementation notes.**
- File: new `cmd/eth-deposit-tx/send_validate.go` (or co-located in `send.go`).
- Use `errors.Join` or wrap with descriptive context strings to make tampered-field divergence visible to the operator.
- **Split-watch:** if the field-comparison block grows past ~8 fields or you need a separate per-field sentinel, split the decode-and-recover into a helper and the field-comparison into a second issue. Architecture §7.3 lists 9 checks; that's tight against 4 pt.

**Acceptance criteria.**
- [ ] `TestValidateRLP_TypeMismatch`: legacy/AccessList typed tx → exit 2.
- [ ] `TestValidateRLP_SenderMismatch`: re-signed RLP with different key → exit 2.
- [ ] `TestValidateRLP_ChainIDDivergence`: tampered JSON `chainID` → exit 2 (the divergence shows JSON vs decoded).
- [ ] `TestValidateRLP_ToDivergence`: tampered JSON `to` → exit 2.
- [ ] `TestValidateRLP_NonDepositContract`: decoded To ≠ netParams contract → exit 2.
- [ ] Happy path: well-formed signed.json → returns decoded `*types.Transaction`, nil.
