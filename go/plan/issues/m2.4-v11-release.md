## Issue M2.4-1 — (Optional) `--withdrawal-address` 0x02 prefix support (EIP-7251) (split-watch)

- **Points:** 4
- **Priority:** P2 (optional)
- **Closes:** PRD §11.4 / project-plan §M2.4 optional scope
- **Depends on:** M0.4-8 (range constants already shipped)

**Description.** If EIP-7251 spec is settled at time of work: implement `--withdrawal-address` with the `0x02` compounding-validator prefix. Extend `Entry.Validate` accepted prefixes. Range constants already shipped in M0 (ADR-005) so this is additive.

**Implementation notes.**
- 0x02 deposits accept 32–2048 ETH (vs 32-only for 0x01). Update accept/range checks in `Entry.Validate` and `tx.Validate`.
- New flag form: `--withdrawal-prefix=0x01|0x02` or extend the existing `--withdrawal-address` semantics. Pick during issue start.
- Update USER-GUIDE worked example.
- **Split-watch:** if spec is still in flux at time of M2.4 start, **defer to vNext** rather than risk shipping a non-final encoding. Decision recorded in this issue's PR description.

**Acceptance criteria (if implemented).**
- [ ] `Entry.Validate` accepts 0x02 prefix with valid shape.
- [ ] `tx.Validate` mirrors.
- [ ] Range constants honored (32 ≤ amount ≤ 2048 ETH for 0x02).
- [ ] Cross-validate lane (M1.7) green for 0x02 fixtures.
- [ ] USER-GUIDE example added.

**Acceptance criteria (if deferred).**
- [x] PR description records the deferral decision + EIP-7251 spec status at time of M2.4 start.
- [x] CHANGELOG v1.1.0 notes "0x02 support deferred to vNext".
