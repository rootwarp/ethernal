## Issue M0.11-1 — `make e2e-testnet` real-hoodi run (success + revert + timeout)

- **Points:** 2
- **Priority:** P0
- **Closes:** PRD §12 M0 exit criterion
- **Depends on:** M0.10-1

**Description.** Run `make e2e-testnet` against a real hoodi RPC three times: (a) happy path success → exit 0, (b) receipt-revert path → exit 5, (c) abbreviated-deadline receipt-timeout → exit 5. Verify zero secrets in any artifact directory (grep).

**Implementation notes.**
- Use a self-hosted hoodi RPC per Risk P5 mitigation; document the provider in the release notes.
- Receipt-revert scenario: deposit with malformed signature (won't pass on-chain) or repeated deposit (replay rejected) — pick the most deterministic mock pattern.
- Receipt-timeout scenario: set `--receipt-timeout=1s` so polling fails before any receipt is available.
- Allow up to 3 retries per Risk P5 mitigation.

**Acceptance criteria.**
- [x] Happy-path run: exit 0; deposit data + signed.json + receipt.json all written; receipt shows `status: 1`.
- [x] Revert run: exit 5; receipt.json present with `status: 0`.
- [x] Timeout run: exit 5; no receipt file.
- [x] `grep -rE '(SECRET|0x[0-9a-f]{64,})' "$TMPDIR/eth-deposit-tx-e2e/"` returns no hits (artifacts grep clean).
- [x] Provider documented in M0.11-3 release notes.
